# session 模块

## 职责
agent 运行时核心。驱动「接收输入 → 调 LLM → 执行工具 → 持久化」的主循环，并实现两段式 delivery（steer/queue）、上下文压缩、会话恢复、title 生成、可中断（turn 边界 + mid-tool 硬中止）。

## 边界与非目标
- 不做 HTTP / 终端 IO（由 web/cli/tui 负责）。
- 不直接连数据库驱动——经 `Store` trait 抽象。
- MCP 全链路已实现：server 配置 + 条件性 system prompt 注入（`build_system` 经 `mcp_section` 将适用于当前 `AgentMode` 的 enabled server 信息注入）；MCP 客户端连接/工具发现/工具调用由 `mcp` 模块提供（见下「依赖与接口」）。每个 server 的 `inject_to`（`{parent,explore,build}` 多选，兼容旧值）按 agent 名字粒度同时约束提示段和 `mcp__...` 工具可见性（explore/build 各自独立勾选）；workflow 调度 Agent 始终不获得 MCP 执行工具。仅在 config 至少有一个 enabled server 时建立连接，否则零开销。
- CLI 注册是纯提示注入，不创建工具或执行进程：`Config.cli` 的 enabled、非空条目经 `cli_section` 聚合成 `## Registered CLI`，并按 `inject_to` 多选投递给父 Agent 与 explore/build 子 Agent 的任意组合；`runtime_sections` 与 MCP 段合并后交给 `build_system`。
- skills 经 `skill_context.rs` 在每次 LLM 请求尾部派生 `[skills]` 目录与 `[active skill]` 源路径（仅 Primary、workflow 排除、不落库）；skill 正文以一次性交付门 `skill_context::deliver_body_once` 只在**激活后首个 LLM 轮次**的 payload 尾部携带一次（`[skill loaded] <path>` 标记块 + 可注入正文，超 20K token 整行截断 + `[INCOMPLETE SKILL]` 续读提示），交付即翻转 `SessionState::skill_body_delivered` 门——同 run 后续轮次 payload 零正文（旧实现每轮重附、浪费 token 且缓存不可命中），需要回看时模型按 marker 源路径 `read` SKILL.md；正文绝不落库——run 结束即从 payload 消失（修复过持久化注入导致的跨 run 永久重复提交），`[active skill]` 指针仅在 armed 但正文为空的退化场景出现。`tools::hide_build_subagent` 在 `AgentKind::Plan` 或 task-plan 激活时隐藏 build。正常 run 结束由 `skill_lifecycle::clear_on_run_end` 同步清内存和 store，清除失败通过事件显式上报；异常中断的 task-plan 由 `abort_keeps_skill` 保留以便 resume。`skill_prompt` 是共享 Arc，TUI 修改可在下一 turn 被 runner 读取。

## 关键抽象
- `SessionState`（`src/lib.rs`）：`id/messages/agent/model/config/client(Arc<dyn ChatStream>)/store(Option<Arc<dyn Store>>)/cancel(Option<CancellationToken>)/skill_prompt(Arc<Mutex<Option<String>>>)` + 私有一次性交付台账 `skill_body_delivered`（`set_skill` 每写必复位、resume 初始 false） + `working_dir/last_usage/persisted_count/session_created/ts_origin`（后者私有 bool，默认 false，经 `.ts_origin()` builder 置位——TUI bootstrap 对 tmux 启动的会话设此 flag，使首条 `persist()` 写 `model: None`/`agent: None` 作为 ts 归属标记）。`cancel` 由调用方挂载（`with_cancel`）：web 经 `POST /interrupt`、tui 经双击 Esc 触发；同一 token 在**四处出口**生效：run_loop 循环头 / mid-tool select! / **LLM 流式中**（`run_one_llm_call` 的分块轮询处）/ steer 批应用 Cancelled 路径（`runner/steer.rs`）。**中断契约**：每处出口统一补发 `Status("interrupted")` + 终帧 `Done`——`Done` 的语义是"关 SSE 流的终帧"而非"正常完成"标记，任何出口缺帧都会让订阅方永远等不到收束（回归：`tests/interrupt_emits_done.rs`；硬取消中途不落库空 assistant 的 D2 契约：`tests/hard_cancel_midstream.rs`）。`skill_prompt` 是共享可变状态：TUI 经 `Arc` 克隆直接写入（`set_skill`/`with_skill`），`run_one_llm_call` 每 turn 经 `skill_prompt_cloned()` 读取最新值，经 `skill_context.rs` 合成的尾部瞬时 user 消息注入（`build_system` 与 skill 无关，见上）。此设计修复了 session 运行中激活 skill 不生效的 bug（旧设计经 cmd channel 发送 `SetSkill`，worker 阻塞在 `run_loop` 内无法及时处理）。
- `record(&mut self, msg)`（`src/lib.rs`）：push 到内存 + 若有 store 则持久化（best-effort，失败仅 warn）。runner 所有 message 入口都走它。内部 `persist()` 首次落库建 session 行：`ts_origin == true` 时写 `model: None`/`agent: None`（durable ts 归属标记），否则写 config 的 model/agent——故 ts 会话行由首条 `record()` 惰性创建，`ts_start` 不再预置 DB 行。
- `SessionEvent`（`runner/event.rs`，21 个细粒度 kind）：SSE/持久化的**单一真相源**三方法——`sse_kind()`（如 `llm_round_start`/`llm_round_end`/`text_delta`/`subagent_child`）、`sse_data()`（与 SSE 线格式一致的 JSON payload）、`coarse_kind()`（12 变体 `EventKind`，仅作 DB `type` 列与回退）。每次 provider/model 调用前发 `LlmRoundStart{started_at_ms}`；无工具轮在 assistant 完成后发 `LlmRoundEnd`，工具轮在该消息请求的整批工具全部完成后发 end，错误/取消路径同样闭合。两事件只描述运行生命周期，不写入 `Message` 或模型 context。web 与 TUI 都走同一事件映射，使 live 广播与 replay 的 kind/payload 一致；store 的 `sse_kind` 列保住细粒度（旧记录 `None` 时回退 coarse）。
- **plan 严格只读契约**（`prompt.rs`、`bash_guard.rs`、`runner/execute.rs`、`runner/subagent.rs`）：Environment 仅对 plan 注入 `MODE: plan (read-only); IN_PLAN_MODE=true`，act 完全省略 mode 行。plan 下所有未准入工具（含 edit/MCP）、build 子 agent 与 bash 持久写效应都在执行前返回 canonical `ToolOutput::err`；错误随 Tool 消息进入下一轮模型 context，明确要求不可换写路径重试、继续只读分析并只输出 plan。session 的 shellguard adapter 会继续拒绝 sandbox 原本放行的 `/tmp` 写入；精确 `/dev/null` 与 fd 重定向不保存状态，仍按只读处理。
- **事件缓冲 flusher**（`src/event_sink.rs`，导出 `EventSink`/`spawn_event_flusher`/`run_flusher`）：把 O(tokens) 的 token delta 落库降到 O(turn)。UI/SSE 实时投递路径（`on_event`）完全不动——每事件仍实时转发；只有磁盘路径走批量。`EventSink` 是可 clone 的 unbounded-channel push 句柄；`run_flusher` 只缓冲 `TextDelta`/`ReasoningDelta`（均 coarse-map `EventKind::TextDelta`），其余类型立即 flush；阈值 `DELTA_BATCH=512`/`DELTA_BYTES=8KiB`。无损契约：丢弃所有 sink clone + `await` flusher 句柄即保证剩余缓冲全落库（turn 边界/channel close 触发最终 flush）。崩溃最坏丢失当前 turn 少量未 flush delta，权威文本仍经 per-turn `messages` append 落地。调用方（TUI `worker`/web `handle`/headless）在 `on_event` 闭包内 `sink.push(&ev)`，run 结束后 `drop(sink)`+`flusher.await`。subagent（`runner/subagent.rs`）与 replay（`resume.rs`）子事件路径直接用 `run_flusher`+unbounded channel。
- `run_loop`（`runner/mod.rs`）：drain 主循环。每轮顶部：① cancel 检查（turn 边界，web/tui 触发）② **claim_steers**（提升 pending steer：只读 `pending_inputs` 轮询保留 cancel-guard，变更 `promote_inputs` 移出 select 不与硬取消竞速——biased select 中途丢弃其 BEGIN→UPDATE→COMMIT 事务会造搁浅行；safe provider-turn boundary）③ 压缩判定 ④ 单次 LLM 调用 ⑤ 工具执行（**一批 tool_calls 并发**：`FuturesUnordered`，每个 future 开头 `yield_now().await` 保证全部被调度（否则快速响应退化为串行），`ToolStart` 按调用顺序预声明、`ToolEnd` 按完成顺序 emit，结果按原始 index 重排保证 Tool message 确定性；事件经共享 `Sink`——`Arc<Mutex<&mut (dyn FnMut+Send)>>` + `emit`——多发并发安全）⑥ 若无工具调用（idle）→ **claim_one_queued**（恰好一条，返回 `(seq,input)` 并 emit `QueueConsumed{seq, text}`（`text` 为 prompt 原文，供前端激活瞬间回显） 让前端即时收缩 pending 镜像）：控制命令（/act、/plan、/act_clear_context）直接应用不耗 LLM turn、可连排；真实 prompt 记录一条后于下一 idle 边界发 `Done`——**queue 为 FIFO 逐条排空路径**：真实 prompt 的 turn 跑完回到 idle 边界继续取下一条，直到队列空才发 `Done`（steer 则是清空路径：`claim_steers` 在每轮 turn 边界一次性提升全部 pending steer）。硬中止：`run_one_llm_call` 的流接收循环与 `execute_call` 的工具 `.await` 均包在 `tokio::select!` 中监听 `await_cancel(session)`；触发后前者回空 turn、后者回 `interrupted` 工具结果；工具批在 cancel 下仍 **drain 至完成**（不 break——否则丢弃在飞 subagent future 会漏发 `SubagentEnd`/`complete_subagent_task` 并留下无 result 的 tool_use），run 在下一轮顶部 cancel 检查收尾。bash 工具设 `kill_on_drop(true)`，select! 取消即丢弃 future → 杀子进程。**bash 进程经 `pre_exec(setsid)` 自成新会话/进程组（load-bearing：否则子进程仍共享控制终端、能直写 `/dev/tty`——sudo 提示/进度条/后台子进程的输出绕过 pipe、落到 alt 屏光标处即 TUI composer/input 区，正是『输出跑到输入区』bug 的根因；新会话令 `/dev/tty` 不可用、强制所有输出走被分捕的 pipe）**。**bash 前台 deadline 默认真实 130s / 展示 120s，并可由命令文本有界推导**：既有静默前缀 `timeout N; command` 优先、执行前剥离且统一限制到生产 120–600s；否则只识别 shell statement command position 上未引用的 GNU `timeout N`（30–600s）或 `sleep N`（N 加 120s 后整体限制到 30–600s、上限 600s），引号、注释和普通参数不触发，扫描无正则/无分配。超时仍不杀进程，而由 `bg::handoff()` 交给后台 supervisor。 bash 仍豁免 runner 的 600s 叶级工具安全网（`execute.rs::DEFAULT_TOOL_TIMEOUT`，自带更短超时）。runner 层**连续 bash-timeout 去重**：`dedup_consecutive_bash_timeouts()` 在连续 bash 超时结果中仅保留**第一条**完整内容，后续替换为第一条（同 pid/同输出文件，模型读同一文件）；非超时 bash 结果重置 streak，非 bash 工具**不**重置；状态 `bash_timeout_first` 跨 turn 持久化。spawn 后立即 `bg::register(pid, pgid, session_id)` 使 `/ps` 能列出、`/stop` 能强杀**正在运行**的命令；`wait()` 返回时 `bg::unregister(pid)`（幂等——若 `/stop` 已先 `kill_all()` 移除条目则为 no-op）。前台阶段仍用共享 `Arc<Mutex<BgState>>` 增量缓冲 stdout/stderr（drain task 缓冲避免管道写满阻塞 `wait()`），无 file 模式。自然完成时先 `kill(-pgid, SIGKILL)` 强制 EOF（清继承管道写端的孙进程——否则 `cmd &` 留孙进程持管致 drain 永久 hang，而 bash 豁免 runner 安全网无兜底），drain 限 2s 有界等待（与 `bg::handoff` 同上限）。`setsid` 仍使 pid==pgid（load-bearing：隔离 `/dev/tty`，且 `kill(-pgid)` 一击尽杀整棵后代树）；`kill_on_drop(true)` 仅杀直接 bash 子，作 select! cancel / future drop 的硬中止回退。全局注册表 `OnceLock<Mutex<HashMap<pid,BgEntry>>>`；TUI `/stop` 调 `bg::kill_all()` 强杀全部已注册组，headless `run.rs` 第二次 Ctrl-C 强退时 `bg::cleanup_all()`（=kill_all + 删 temp 文件）。子 agent 复用父 token（`child.cancel = parent.cancel.clone()`）。doom-loop 守卫：`DOOM_THRESHOLD=20`（定义于 `runner/event.rs`），滑动窗口内同批工具 `name:input` 签名连续 20 个相同 → emit `Error` + 为整批合成错误 Tool 结果（`doom-loop: tool execution skipped`，chat API 要求每个 tool_use 都有配对 result）+ 返回 `Err` 终止 run。**tool-failure 守卫**（`src/tool_guard.rs` + `core::ToolGuardConfig`，默认 `max_consecutive_failures=20`）：run_loop 维护每轮 `FailureMap`（按工具名），工具结果批后调 `tool_guard::record` 记录——成功清零、失败递增；达阈值即发 `SessionEvent::Error` 并 `break` 中止当前 turn，失败间施加指数退避（`backoff_base_ms*2^(n-1)`，封顶 `backoff_max_ms`）。与 doom 守卫互补：doom 按 `name:input` 签名，本守卫按工具名，故模型微调入参仍能被拦。设阈值为 0 禁用。**plan 只读 bash 写拦截**：`execute_call` 在 `AgentKind::Plan` agent 调 bash 前调用 `bash_guard::classify`，若为写命令（文件重定向 `> file`/`>> log`/`&> out`、`tee <真实文件>`、变异/git写/包管理/就地编辑）则返回 canonical `plan_denial` 错误给模型（"Blocked in plan mode (read-only): … Do not retry … delegate read-only investigation to an 'explore' subagent (task tool) … switch to the act agent (/agent act)"），不执行。判只读：fd-merge（`2>&1`/`1>&2`）与重定向到 `/dev/null`（含 `tee /dev/null`、裸 `tee`）——bash 工具已分捕 stdout/stderr 故无副作用；此判定在子 shell/花括号组内同样生效（`read_redirect_target` 在 `)`/`}`/`]`/`#` 处干净终止，不再误吞元字符）。**agent 切换 = 纯控制命令**（`/act`/`/plan`）：只改状态 + 持久化 + 发 `AgentSwitch`，**不折叠 transcript、不发 `TranscriptReset`**（`tests/agent_switch_roundtrip.rs`）；折叠只由 ClearContext 控制命令触发（见下「模式控制命令」），prompt 注入 `IN_PLAN_MODE` 只读标记（`prompt.rs`）。
- **autopilot 三态分发**（`runner/mod.rs::run` 尾部 + `autopilot/review_pass.rs`）：初始任务完成后按 `config.autopilot.mode`（core 三态枚举 `ApMode`，旧布尔 `enabled` 在 config 合并层迁移）分发——`ap` → `autopilot::drive` 自驱 PLAN→ACT→VERIFY 循环（PLAN 阶段 = **plan agent** + 激活 **task-plan** skill（顺带解锁 latent `question`）+ continuation prompt；ACT 阶段经 `handoff.rs::reset_to_directive` 把探索 brief 折叠为单条执行指令，无 brief 时回退注入 execute prompt）；`review` → `review_pass` 一次性 review turn（**任意模式可跑**——act-only 门控已删除：reviewer 留在完成初始任务的当前 agent，不切 agent、不折叠 transcript，读-only 故 act/plan 均可；激活 review skill + 合成 review prompt 跑单次 `run_loop`；入口 pre-flight cancel 检查（已取消则零副作用——不切 agent、不注 prompt——仅清 skill + `Done`，对照 drive 取消路径）；结束**Ok/Err 双路径**清 skill（`clear_injected_skill`：内存 + `clear_skill:true` 落库，防 resume 复活系统注入的 skill）并发 `Done`，事件 `AutoPilot{phase:Review, iteration:0}`，不进 ACT/VERIFY）；`off` → 不接管。**子会话强制 Off**：`run_subagent` child 与 `resume::replay_child` 显式把 `config.autopilot.mode` 置 Off——autopilot 是顶层编排，子会话只跑 scoped task（`drive::finish` 同样走 `clear_injected_skill` 落库）。`ApPhase` 枚举含 `Review` 变体，CLI/TUI 渲染走既有 `{phase:?}` 泛化路径无需特判。
- **subagent**（`runner/subagent.rs::run_subagent`）：`task` 工具创建独立 child SessionState（explore 只读 / build 实现，默认 explore）。plan 只暴露和允许 `explore`；任何其它类型在 `resolve_agent` 前以 canonical plan 只读错误拒绝，不启动 child，也不在 valid options 中广告 build。子事件经 `SubagentChild` 包装转发，父级可观察完整 child 生命周期；多个 tool call 经 `FuturesUnordered` 并发，结果仍按原始 call 顺序回填。若有 store，会建立 child session 与 `subagent_tasks` 记录并持久化子事件。超时/turn cancel/hard cancel 走两阶段取消：先通知 child 并给 `subagent_drain()` 宽限清理，超时后才由 `force_cancel_subagent` 收敛 DB、registry 与 `SubagentEnd`。
- **sidecar 旁路问答循环**（`runner/sidecar.rs`，TUI `/sidecar <question>`）：`SidecarConv{ id: "sidecar-<ulid>", child, registry }` + `run_sidecar_turn`（free fn）。三条契约：**Snapshot-in**（child 从父 transcript 克隆或调用方快照起步，follow-up 复用同一 conv 内存延续 Q/A）；**零持久化**（child 永不 `.with_store()`；`SidecarStart/Child/Turn` 三帧经 `SessionEvent::is_sidecar_frame` 在 `EventSink::push` 与 TUI `worker::persist_event` 双口子丢弃）；**成本记主任务**（child 每轮 `LlmUsage` 裸转发不包 `SidecarChild`，下游按主任务轮次累计并持久化）。child 的 `Done`/`Error` 被吞掉（`Error` 只落入 `SidecarTurn{ok:false}`），控制命令问题在入口拒绝且不调 LLM。
- **subagent steer admission gate**（`subagent_steer_gate.rs`）：每个运行中 child 以 call_id 注册 `SubagentSteerGate`。Enter 型 steer 在异步 store 写入前取得 reservation，成功 commit 后推进 epoch；child 的最终 idle 边界只有在 epoch 未变化且无在途 reservation 时才原子关闭。reservation 先赢则 runner 等待并消费，关闭先赢则调用方拒绝或回滚刚写入的 row，保证不存在“API/TUI 已接受但 child 已退出”的永久 pending steer。硬中止与强制清理会 force-close 并移除 gate。
- `compaction::should_compact`（`src/compaction.rs`）：双信号——token 估算（首轮即可触发，无需模型回传 usage）+ 模型回传 `last_usage.input_tokens`（**非** `total_tokens`，避免输出重的 turn 误触输入预算）；预算 = `min(context_threshold, context_limit - reserved)`，故 `reserved` 真正缩减可用窗口（不再是死字段）。摘要用 `small_model`。**摘要提示词为结构化模板**（`prompt::compaction_system_prompt` + `prompt::compaction_user_prompt`）：系统提示固定 anchored-context-summarization 角色；用户提示要求严格按 Objective / Important Details / Work State(Completed/Active/Blocked) / Next Move / Relevant Files 顺序输出 Markdown。`compact()` 先在 head 中查找既有合成 summary 消息（`[Conversation summary so far]` 前缀），剥前缀后经 `<previous-summary>` 块传入，summarizer **增量更新**而非重写。`compact()` 经 `compaction_split()` 决定切分点：当 turn 数 > `tail_turns` 时取理想轮界切分；**turn 数 ≤ tail_turns 但已超阈值时不再静默放弃**——改为回退压缩最旧一轮（或单轮时保留最近一条消息、压缩其前内容），保证超预算的短轮次对话仍被压缩而非整段塞给模型。`None` 仅当真正无可压缩（空或单条消息），caller 不 emit 任何事件；**`None` + 超预算的收敛**（2026-08-19 fix）：transcript 折叠点（`after_handoff` 清空上下文折叠、`after_compaction` 压缩）重置 `last_usage = Usage::default()`，消除 stale-reported 对单条合成消息误触 `should_compact`；runner `Ok(None)` 分支只在当前 transcript 估算（`estimated_tokens`，现为 `pub(crate)`）**超过 provider 硬 context limit**（请求必然 400）时才 Err+Error 事件，估算低于硬 limit 时直接继续发 LLM 请求（compaction 预算≠硬上限）——不再误杀「单条巨消息仅超预算」或「清空上下文后陈旧上报」的回合。`Some(summary)` 时 runner 发 `TranscriptReset(new_msgs)` + `Compaction(summary)` 两个事件——TUI 收到 `TranscriptReset` 时清空 `chat.blocks` 并用 `replay_into_chat` 重建（显示与模型视图一致）。 **图片保留契约**：`compact()` 先经 `collect_head_images(head)`（上限 `MAX_PRESERVED_IMAGES=4`，取最近）收集 head 中用户/工具图片 URL，再经 `strip_images()` 把所有图片块从送入 summarizer 的输入中剥离（避免图片被摘要吞掉/计费），最后把保留的 ≤4 张图片作为 `image_url` 块附加到合成 summary 消息（`has_image()` 为真）。`resume()`（handoff 与 compaction 两条分支）与 live `handoff` 折叠对重建的合成消息同样 re-derive head 图片并附加——跨进程恢复后图片不丢。
- `streamline::streamline`（`src/streamline.rs`）：纯函数确定性精简——在 `run_loop` 内 LLM 调用返回后、`record` 持久化前，对完成的 assistant 文本做保义归一（live `TextDelta` 已投递原文，故 UI 所见不受影响，仅持久化 + 后续上下文副本被精简，与 compaction 把旧消息替换为摘要同范式）。散文行去尾空白、连续空行收敛为单行、首尾空白行裁剪；**fenced 代码块（` ``` ` /`~~~`）逐字节透传**，代码格式/缩进/嵌空行不动。配置 `OutputStreamlineConfig`（默认开启，`collapse_inline_ws` 默认关）；每条规则在 clean 文本上为 no-op，故既有 transcript 零回归。
- **reasoning_effort 出站透传 + 交错思考**（`runner/llm_call.rs::run_one_llm_call` + `runner/mod.rs`）：主 LLM 调用把 `session.config.reasoning_effort`（`low|medium|high`）写进 `ChatRequest`，由 llm 的 `to_body` 发顶层字段（OpenAI 风格思考深度）；`compaction::summarize` / `resume::generate_title` 后台调用显式置 `None`。`run_one_llm_call` 返回 4-tuple `(text, reasoning, tool_calls, usage)`——reasoning 从 `LlmEvent::ReasoningDelta` 累积。**交错思考**（`interleaved_thinking` 默认 `Some(true)`）：`run_loop` 在工具调用 turn 且 reasoning 非空时，将 `ContentBlock::Reasoning { text }` 持久化到 assistant 消息（Text 之前），经 llm 的 `push_assistant` 序列化为 `reasoning_content` 在后续请求回传——DeepSeek-V4 强制要求此行为（否则 HTTP 400）。非工具 turn 不持久化（API 忽略，省 token）。运行时热重载：调用方（TUI `/config`/`/model` 经 `UiCmd::ReloadConfig`）在 turn 边界调 `SessionState::apply_config_reload(cfg, new_client)` 原地替换 `client/model/config`。每条出站 LLM 请求还携带 per-agent `cache_salt`，由 `cache_salt_for(session)` 派生为 `<agent_name>:<session_id>`——主 agent turn、子 agent turn（child session id，每个子 agent run 得独立 `sub-<ULID>` 命名空间）、title 生成、compaction 均注入；开关 `Config.cache_salt`（默认 `Some(true)` 即开，env `OPENCODER_CACHE_SALT` 覆盖），让 vLLM / prefix-cache 后端按 agent 区分 KV 缓存、会话内前缀逐轮增长。
- `resume::resume`（`src/resume.rs`，低层原语）：从 Store 重建 SessionState，model/agent 取自存储的 session meta（忠实原配置）。重建时两条 reconcile 路径：① 卡在 `Running` 的 subagent task（进程在 subagent 中途被打断）标记为 `Failed("(interrupted)")`；② 悬空的 `tool_use`（assistant 请求了工具但 tool_result 未落盘）合成 error `ToolResult`，避免 provider HTTP 400。这两条仅在裸 `resume` 直调时生效，是 `resume_and_replay` 之下的安全网。
- `resume::resume_and_replay`（`src/resume.rs`，高层入口；CLI headless 与 web 的 resume 走它；TUI 的 `/task` 切换与 `-s` 启动改走裸 `resume` 纯加载，pending 子代理留给下一轮 prompt 的 `replay_cancelled_tasks`）：先遍历父 session 所有 `Running` subagent task（`list_subagent_tasks` 按 `seq` 升序），逐个 `resume(child)` + `run(child, "")`（**只此一层、不递归**——子 agent 无 `task` 工具，不可能派发孙任务），把子结果回填进父 transcript 的**单条** Tool message（mirrors `run_loop` 把一轮工具结果批进一条 tool_msg 的语义），并 `complete_subagent_task`。回填发生在裸 `resume` 之前，故 `resume` 跑到时无 `Running` task、task 的 `tool_use` 也已 answer，两条 reconcile 路径对该 turn 失活——既不重复标 Failed 也不合成 error。子续跑的 messages/events 落到子 session（与 `run_subagent` 同 pattern）。签名 `replay_cancel: Option<CancellationToken>`：逐个 `replay_child` 前检查 token，已 cancel 即 break（剩余 Running task 留待下次 resume）；该 token 透传给 `replay_child` 作 `parent_cancel`。`replay_child` **有总体超时 + 可中断**（修复恢复卡死）：`select!` 把 `run_with_registry` 与 `config.replay_timeout()`（默认 300s，独立于 `task_timeout` 1800s）及 `parent_cancel` 竞速；child 现自带 `CancellationToken`（`resume` 重建时为 None，此处补装——否则 run loop 中断检查永不触发），任一非 run 分支胜出则 cancel child + drop run future（硬中止进行中的 LLM/tool 调用），返回 `(部分文本, false)` → 调用方 `complete_subagent_task(ok=false)` 标 `Failed` 并回填 error `tool_result`；权威文本已由 `session.record()` 落库故可恢复。`flusher.await` 加 30s 超时防 DB 写慢永久阻塞。CLI 把 token 创建**提前到 resume 之前**并传 `Some(...)`（Ctrl-C 挂同一 token，恢复阶段可中断）；TUI/Web 也传 `Some(token)`，即便 token 不显式 fire 亦有 300s 超时兜底。`generate_title` 用 small_model 异步生成标题。测试：`tests/resume_replay_timeout.rs`。
- `resume::replay_cancelled_tasks`（`src/resume.rs`；由 `run_with_registry`（`runner/mod.rs`）在 drain turn 进入 `claim_steers` **之前**调用）：收集父 session 的 `Cancelled` subagent task（经 handoff 孤儿过滤——`handoff_seq.is_some()` 时要求 task 的 `tool_use` 仍存在于 `session.messages`；且先过滤掉 `tool_use` 已有匹配 `tool_result` 的 task——如超时 subagent 父侧已回填超时错误结果，重跑会追加重复 tool_result 触发 provider HTTP 400），分两支：① **无 pending steer**（`store.pending_inputs(id, Delivery::Steer)` 为空）→ 逐个 `replay_child` 跑完（把 `session.cancel.as_ref()` 作 `parent_cancel` 传入，受 `config.replay_timeout()` + 取消令牌双重守护），回填 `tool_result` + `complete_subagent_task`（硬中止/崩溃续跑语义，正确不应删）；② **有 pending steer** → 调 `abandon_cancelled_tasks`：**不重跑**子 agent，直接为每个 task 回填终态 error `tool_result`（"cancelled: the user redirected this turn (steer)."，保证 transcript 无悬空 id）并把 task 标 `Failed`，使 drain turn 立即落到 `claim_steers` 消费用户重定向。这是 **steer-click-hang 修复**（旧逻辑对 `Cancelled` task 一律 replay，导致子 agent 在用户已提交 steer 的 drain turn 被静默重跑、占用工具回合、steer 被无限挂起）；标 `Failed` 而非 `Cancelled` 使该 turn 永不被再次 replay。子 agent 无 `task` 工具 → `Cancelled` 列表恒空 → 对子进程零影响。测试：`tests/resume_replay.rs::{replay_cancelled_tasks_abandons_when_steer_pending, *_cancel_token_fired/not_fired}`。
- **transcript 折叠（`src/handoff.rs`；无持久化阶段状态）**：执行指令折叠 `handoff::reset_to_directive(session, extra)` 取最新**非 synthetic**、非空 assistant 文本为 brief，打包成单条 synthetic user 执行指令（`HANDOFF_PREFIX` + brief + 可选 extra），供 autopilot ACT、web `POST /handoff` 与 plan 模式 ClearContext 复用；无真实 assistant 文本返回 `None`。ClearContext 的分支语义由当前 agent 决定：plan 下保留最新真实计划为执行指令并切到 act；act 下保留最新非空 assistant 文本（synthetic 也可）为中性 continuity seed；完全无 assistant 内容时不再无条件覆写为 fresh-start 哨兵：若 `handoff_plan` 已持有非哨兵、非空边界（指令 display 或种子标记）——即二次 clear / resume 后再 clear / act 未产出文本时 clear，transcript 只剩 synthetic 消息、`last_assistant_text` 必然落空——则按原边界原样重折（`handoff_message(prev)` / `seed_message(clear_seed_text(prev))`，与 resume 重建同款），仅当从未保留过边界时才落 fresh-start 哨兵。两路都重置 `session.messages`、写 `handoff_seq`/`handoff_plan`、清 compaction/skill 元数据，原始 store 消息保持 append-only；`resume()` 按 plain brief、种子标记 `<<OPENCODER_CLEAR_SEED>>` 或哨兵 `<<OPENCODER_CLEAR_CONTEXT_MARKER>>` 重建唯一焦点消息。
- **无持久化 plan 阶段计数器**：act/plan 双模式仍存在，但 `src/plan_phase.rs` 与 `plan_snapshot`/`plan_input_count` 运行时读写已移除；schema v10 的两列仅为旧库兼容。计划交接直接从当前 plan transcript 的最新真实 assistant 文本提取，不依赖 arming 计数器。interlude 存量 `agent='sandbox'` 行在 store 读路径归一为 `plan`（见 [agents/store](../store/index.md)）。
- **plan 模式 bash 写拦截（`bash_guard`）**（`src/bash_guard.rs` + `runner/execute.rs`）：`AgentKind::Plan` 执行 bash 前以本次调用的生效 `workdir` 调 `classify_with_dir`，分类 cwd 与执行 cwd 严格一致。独立 [`opencoder-shellguard`](../shellguard/index.md) 保持 sandbox 判定与 `/tmp` release 兼容，同时在 `Verdict::writes_state` 上保留可组合的写效应；session adapter 将有写效应的 `Allow` 及全部 `Ask`/`Deny` 映射为 `WriteBlocked`，所以 `/tmp` 持久写入也不能穿透 plan。拦截返回 canonical model-facing tool error，明确操作未执行、不可换路径重试、只输出 plan，并把上下文获取路由到只读 `explore` 子代理（`task` 工具）而非 bash；精确 `/dev/null` 与 fd redirect 因不保存状态仍是 `ReadOnly`。`cd` 本身无文件系统写效应且 analyzer 会按 `cd` 目标重瞄后续分析 cwd（`extract_cd_target`），故静态可解析目标（字面相对/绝对路径、含 `$VAR` 经 resolve 展开后的字面值）的 `cd` 为 `ReadOnly` 放行；不可解析目标（未定义变量、`~`、无参回 home、未知 flag、`popd`，`pushd` 保留 scoping）仍 fail-closed 拦截。**bash_guard 是落实 plan 契约的工作流护栏，不是 act 模式的安全沙箱。**
- **工具集**（`src/tools/mod.rs`）：9 个内建工具由 `registry()` 一次性注册：`bash`、`read`、`view_image`、`edit`、`search`、`ls`、`question`、`task`、`ssh_pty`。`schema_for(tools, hide_build)` 按 name 稳定排序；`tools::hide_build_subagent` 在 plan 模式或 task-plan skill 激活时隐藏 `build` 子代理，运行时 guard 同步拒绝绕过，保证只读规划边界。
- **bash 动态前台超时**（`src/tools/bash/timeout.rs`）：保留并优先处理会在执行前剥离的静默 `timeout N; command` 前缀；其余命令只在 shell statement 的 command position 识别未引用整数 `timeout N` / `sleep N`，忽略引号、注释、普通参数、小数和单位后缀。静默前缀生产下保持 120–600s；真实 GNU timeout 把 N 限制到 30–600s；sleep 把 N 加 120s 后整体限制到 30–600s（上限 600s）。扫描不使用正则，推导值同时用于真实 deadline 与 handoff 文案。
- **模式控制命令（`src/control_cmd.rs`）**：`/act`、`/plan` 是纯状态切换（持久化 + `AgentSwitch`，不折叠 transcript；同 agent 重切完全 no-op）。`/act_clear_context` 是 canonical ClearContext，`/clear_context` 为 legacy 别名，均支持复合尾部。plan 下应用顺序为：`reset_to_directive` 保留计划 → 清 skill → session 切 act → `persist_clear` 原子写边界与 agent → 依次发 `TranscriptReset`、`AgentSwitch("act")`；随后 direct/queue/steer 三种入口都让该 synthetic 指令驱动恰好一个 act LLM turn。act 下继续使用中性 continuity seed 且 agent 不变；已保留边界（指令/种子）经 re-clear 原样保留并继续驱动 LLM turn，只有从未保留过任何边界（哨兵）才不调用 LLM。`is_mode_control`/`split_control_prefix` 是 admission 与三入口解析单一真源，控制命令自身不记为普通 user text；queue/steer 可先入队并在安全边界应用，外部直接改 agent 的入口仍受 running gate。

## 主流程
CLI/HTTP 入口 → 建/恢复 SessionState（store 可选）→ `run(session, prompt, on_event)` → run_loop 循环到 Done / interrupt / doom-loop 守卫 → （CLI）异步 generate_title。

empty prompt = drain / continuation 模式：不 push 合成 user msg，直接进 run_loop（web drain 依赖 store 中已 admit 的 steer/queue 提供输入；TUI plan 模式 Shift+Tab 派发 `/act_clear_context`（act 下 Shift+Tab 是切 plan 的纯模式切换，不派发），plan 指令或 act continuity seed 置 `handoff_pending` 后执行，无内容哨兵则停在干净状态）。

## 两段式 delivery：steer / queue drain 契约

steer 与 queue 都是「先以 pending 落库（`admitted_seq` 列、`promoted_seq=NULL`），消费后逐条落账（`mark_inputs_recorded`）；run 入口 `input_recovery::recover_orphaned_inputs` 把 promoted 未落账的孤儿行翻回 pending，run_loop 在合适边界才 promote 进历史；**失败零重提交**：run Err 直接终止，不做错误路径 re-absorb、不发起新 LLM 请求——未消费行保持 pending、已 claim 的消费失败行由 P1-3 原地 unpromote 兜底，由下一次成功 run 消费（成功路径 P1-4 `reabsorb_tail` 保留）」的延迟提交机制，但消费规则截然相反。权威实现：`claim_steers`（`runner/steer.rs`）/ `claim_one_queued` 与 drain 步进（`runner/drain.rs`），drain 主循环在 `run_loop`（`runner/mod.rs`）。

- **入口优先级（`runner/drain.rs::entry_drain_mode`）**：空 prompt（纯 drain 重启）且有活跃 skill 时（skill 为 one-shot：仅存活于触发它的 run，结束由 `skill_lifecycle::clear_on_run_end` 从内存与 `sessions.skill` 清除；此处指 drain 入口仍武装的 skill，如 resume 恢复或 pre-set），**pending steer/queue 优先于 SKILL_TRIGGER 重注入**（FIFO 先排空，不先跑 skill turn）——否则 TUI `drain_pending`/web `drain_to_completion` 每轮重注入 trigger、永不弹队列，形成「同一 skill 反复重激活」的自续循环。pending 轮询仅在「纯 drain + 有 skill」分支发生（`!has_skill` 短路），文本 turn 零额外 store 读。无 pending 的空提交仍注入 trigger 续跑 skill。另有 `MAX_CONSUME_STREAK=32`：连续无进展的 drain `ConsumeNext` 步（裸命令/late pending 复查）超限强制 `Done`，防 claim 持续失败热自旋。测试：`tests/skill_queue_drain.rs`。
- **`$skill` 消费时激活（唯一权威）**：queued/steered/直发 prompt 里的 `$name` token 只在**消费时刻**由 `skill_resolve::record_compound`（drain/steer 吸收边界）或 runner 直发路径的 `resolve_inline_skills` 解析——激活（`skill_prompt` + `active_skill_names`）并 `persist_active_skill` 落盘（只写不清；清 `skill` 归 control_cmd 的 ClearContext/TUI `$` 菜单）。admission 层（TUI queue/steer、web prompt 文本）一律存**原文**（token 保留），故 mid-turn admit 的 `$skill` 不影响当 turn 已发出的请求、边界吸收后才生效（`tests/steer_skill_deferral.rs`、`tests/plain_skill_prompt.rs`）。消费边界同时把**原样输入**（mention 展开后）写入消息 `display`（回显单一真源）：`record_compound` 两路径与直发路径（resolve 前捕获 raw）均落；纯 skill 提交经 `entry_drain_mode` 注入的 SKILL_TRIGGER（synthetic）携带 verbatim display（`tests/skill_display_verbatim.rs`）。
- **steer =「一把全吸收」**：每个 turn 边界顶部（cancel 检查之后、LLM 调用之前）调 `claim_steers` → `promote_inputs(sid, max_seq, Steer)`，SQL `... WHERE delivery='steer' AND promoted_seq IS NULL AND admitted_seq <= max ORDER BY admitted_seq ASC` 一次把**全部 pending steer** 提升进历史，逐条 emit `SteerConsumed{seq, text}`（seq 为 `session_inputs` 主键，让前端按身份收缩 pending 镜像）。steered 控制命令（`/plan` 等）防御性 apply、**不记为 user text**。无每 run 配额——多少条都在同一个边界吃掉。
- **queue =「FIFO 逐条排空，空才 Done」**：仅在 **idle 边界**（本轮 `tool_calls.is_empty()`）才进 drain；`claim_one_queued` → `claim_next_queue` 每次原子取一条。纯 `/act`、`/plan` apply 后不耗 LLM turn；`/act_clear_context` 若产生 plan 执行指令或 act continuity seed，则该 synthetic 输入占一个 turn，只有空白哨兵为零 turn；真实 prompt 每条各跑一个 turn。turn 完成后继续取下一条 FIFO，直到队列空才发 Done。steer 在 turn 顶部批量提升，ClearContext synthetic 输入与 direct/queue 保持同一续跑语义。

| 维度 | steer | queue |
|---|---|---|
| 触发边界 | 每个 turn 边界顶部 | 仅 idle 边界 |
| 单次消费 | 全部 pending（`admitted_seq <= max`） | 恰好一条（`LIMIT 1`） |
| 每 run 配额 | 无限制 | 无限制（FIFO 逐条排空至 Done） |
| 控制命令 | apply 不入历史（防御性） | apply 不耗 turn，可连排 |
| 打断进行中 turn | 能——`turn_cancel`（子 agent `>` submit-now）经 LLM 调用与工具批的 `select!`（`await_turn_cancel`）短路，下一边界 `claim_steers` 吸收 | 否——必须等 idle |

测试锚点：`steer_followup.rs`（`steer_promotes_at_turn_boundary`、`multiple_steers_at_one_boundary_promoted_once`——3 条 steer 同边界全部提交、`queue_drains_all_fifo_in_single_run_then_done`、`steer_consumed_carries_pk_seq_not_admitted_seq`、`durable_pending_input_survives_until_drain`）；`control_cmd.rs::queue_drains_control_cmds_between_real_prompts`（队列 `[/plan,prompt,/act]`：前导控制命令不耗 turn、真实 prompt 跑 turn 后继续排空、尾部 `/act` 同样被应用，队列清空才 Done）。

## 依赖与接口
- 依赖：opencoder-core、opencoder-llm（ChatStream）、opencoder-store（Store）、tokio-util（CancellationToken）。

- 被依赖：web（drain_to_completion）、cli（run_headless / resume）、tui（run_headless / resume）。
