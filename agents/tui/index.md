# tui 模块

## 职责
ratatui + crossterm 交互界面。3-region 布局、事件循环、鼠标命中测试、键盘分发、subagent 可折叠 + ctx 切换。

## 边界与非目标
- 不在事件循环内联等待 Store 写锁：队列类 admit（Tab/Enter-while-running）经 `queue_admitter` actor 离环完成，按键分支只做乐观镜像 + completion 对账（steer 路径暂例外）；其余 Store 交互经 worker `UiCmd` 通道。不持有 SessionState（worker 持有）。
- 非目标：TUI 不是 Web 替代品——app 内无 SSE replay，仅 live event 流；但 **worker 持有 `Option<Arc<dyn Store>>`**，每个 SessionEvent 经 `worker::persist_event`（fire-and-forget spawn）写入 `session_events`（含 `sse_kind`），故 web/SSE 客户端可回放 TUI 驱动的会话（TUI 自身不在 app 内回放）。

## 关键抽象
- `onboarding`（`src/onboarding.rs` + `app_bootstrap.rs`）：交互式启动先确保 `~/.opencoder/config.json` 存在，再对完整有效配置执行凭证、HTTP(S) URL、headers、proxy 与 `ChatClient` 本地构建校验（不发送模型请求）。不可用时在 TUI 内复用 `ProviderForm`，预填有效 provider/model/base_url、掩码密钥并聚焦 API key；保存固定写全局配置，随后重载 project/CLI/env 覆盖并再次校验，成功才创建 Store/Session/worker。Esc/Ctrl-D 直接退出，空配置保留供下次继续。`ActiveTerminal` 把 onboarding 的同一 alt-screen 交给主 chat loop，并以 RAII 同时恢复终端和 tmux status。
- `ChatView`（`src/chat.rs` + `src/chat_stream.rs`）：`blocks: Vec<ChatBlock>` + `agent/status/subagents_running/subagents_total/context_used`。`apply(&SessionEvent)` 逐事件更新——核心接缝；同一 LLM round 可有多个 Thinking，但最多一个 Assistant，交错的 `ReasoningDelta → TextDelta → ReasoningDelta → TextDelta` 会把 Thinking 统一排在前、所有正文 chunk 原样拼入唯一 Say，`LlmRoundEnd` 为硬边界。`track_context` 只累加本 view transcript token（不递归 SubagentChild），Thinking/Assistant 由 `sealed`/`done` 保证只计一次。token 记账双轨：`tokens_total` 为会话累计真实消耗（`LlmUsage` 事件逐轮累加，**含 `SubagentChild` 转发的子代理轮次**；replay 时再叠加重建子 view 总额，floor 取 max 不双计）；`real_context_tokens: Option<u64>` 为最近完成轮次 provider 真实 `input+output`（Compaction/TranscriptReset/ModelSwitch 清空，子代理轮次不写入父 view），状态栏 ctx 优先取它（不加 sys_tokens），无真实数据回退 `context_used + sys_tokens` 估算。`last_open_thinking_collapsed()` 同时识别尾部 Thinking 和位于未完成 Assistant 前的开放 Thinking；首个 reasoning delta 触发绘制，后续折叠增量才跳过重复绘制。
- `ChatBlock`（定义于 `src/chat_types.rs`）：`Marker(Vec<Line>)` / `User{rendered}` / `Assistant{raw,rendered,done}` / `Thinking{text,collapsed,sealed}` / `Tool{header,output,started_at_ms,elapsed_ms}` / `Subagent{id,child_session_id,kind,prompt,view:ChatView,done,ok,summary,started_at_ms,elapsed_ms}`。`flatten_with(anim_tick, now_ms)` → `Vec<Line>` 供 Paragraph 渲染。用户输入统一经 `User{rendered}` 块渲染；Assistant 对应绿色加粗 `❯ Say:`，每轮唯一。`turn_block_start` 标记当前顶层 turn 的块下界，使可靠完成态只校准本轮 Assistant、绝不覆盖历史回答。User/Assistant 正文共用 `indented(rendered, 4)`。
- `terminal_text`（`src/terminal_text.rs`）：动态文本进入 UI 模型时的一次性终端安全边界。`sanitize_multiline` 保留结构换行、展开 TAB 并移除 CR/C0/C1/DEL，`sanitize_single_line` 额外把换行压成空格，`sanitize_line` 在保留 Span 样式的同时净化 marker。普通文本返回 borrowed `Cow`、不分配；live delta 仅扫描当前增量，历史消息仅在 replay 时扫描一次，`flatten_with` / `ViewportCache` / 每帧 render 不重复遍历。原始 SessionEvent、Store 消息和模型上下文不改写。
- `Subagent` block 不可内联展开：始终单行表头 `⇲ subagent [kind] prompt [●/✔/✘ status, N tools] [→ view]`（running=黄● / done=绿✔ / failed=红✘）。点击表头直接进入子会话 ctx 视图（body 渲染子 ChatView + 子 view 自有 context_used/real_context_tokens 与 tokens_total 驱动状态栏——聚焦时只显示子自身消耗与上下文，父视图含全部），Esc / Ctrl+L 返回主进程并回到底部跟随态。
- `MouseHits`（`src/render.rs`）：每帧重算的命中目标——`jump_btn/body/queue_btns/thinking_btns/subagent_btns/tool_btns/compaction_btns`。`record_thinking_hits` / `record_subagent_hits` / `record_tool_hits` / `record_compaction_hits` 映射逻辑行号到屏幕行号（含视口裁剪：滚出可见区不计）。Compaction 块与 Thinking 块共用 `render_collapsible`（`compaction_block.rs`），现已接入同一 click-to-expand hit-rect 管线——点击表头行经 `handle_mouse` → `toggle_compaction_at` 翻转折叠态；折叠 header 显 `{icon} {label} ({N} lines)` 行数摘要，展开 header 仅显 `{icon} {label}`（均无 expand-collapse 提示文字），`Compaction` 标签与展开正文统一为无 BOLD 的紫色。Compaction 块现**流式展开**：`CompactionDelta` 经 `open_compaction_streaming`（`compaction_block.rs`）追加进 `streaming=true` 的展开块——用户在 summary LLM 调用期间即见生成文字；最终 `Compaction(summary)` 事件经 `finalize_compaction` 覆写全文并折叠（`streaming=false`）。故 `CompactionDelta` 不再属可丢弃 delta（`worker::is_droppable_delta`）。
- `KeyBindings`（`src/keymap.rs` + `core::config::keymap::KeymapConfig`）：17 个可重绑定快捷键从 `opencoder.json` 的 `"keymap"` 段加载，坏 spec 回退默认。`switch_mode` 默认 `ctrl+t`，在 act/plan 间纯切换并保留 transcript 与 composer；缺字段的旧配置自动补默认，退役的 `switch_mode_clear`/`switch_mode_keep` 残留键被忽略。`KeyCombo::matches` 继续处理 BackTab、SHIFT-optional Tab 与 Kitty raw 控制字符；`Ctrl+H` 的 `KeymapMenu` 支持捕获、保存、恢复默认与帮助页。
- **copy-mode 正文滚动**（`src/copy_mode/mod.rs`）：Ctrl+G 活跃时，编辑类按键仍只被 copy-mode 消费而不触达 composer/modal；对话正文导航是唯一例外——`scroll_action`/`next_scroll` 以纯函数产出滚动转移，↑/↓ 逐个 clean row、PageUp 向旧内容移动 20 行、Home 到首行，PageDown/End 恢复 `follow=true` 并回到最新。app 把结果写入既有 body `scroll/follow`，`render_clean` 再按 `CleanModel` 的净化后总行数做最终 clamp，故滚动几何与实际可复制文本一致；状态 chip 与帮助页展示导航键。
- `tick_clock`（`src/app_loop.rs`）：只维护 **任务总时长** `task_elapsed_ms`（状态栏 running 动画旁的 warn 橙时长）。`false→true` snap `last_clock` 排除 idle 间隙且不自行重置 task；running tick 累加；终态冻结。任务内可包含多次 provider/model round，逐轮 `[turn cost]` 不再复用此任务钟，而由 `ChatView.llm_round_started_at_ms` 的事件状态独立驱动。
- `consume_modifier_or_release`（`src/terminal.rs`）：事件循环最前的 Shift-suspend 过滤器。Kitty `REPORT_EVENT_TYPES` + `REPORT_ALL_KEYS_AS_ESCAPE_CODES` 使 Shift 按下/释放可检测——Press 时 `suspend_mouse_capture`（DisableMouseCapture → 原生文本选择），Release 时 `resume_mouse_capture`。bare modifier 与非 Shift Release 被吞没（防 ghost double-trigger）。`shift_held` 为 `app.rs` 循环局部 bool。
- `copy_mode`（`src/copy_mode/{mod,clean}.rs`）：终端原生 copy 模式——`Ctrl+G`（`keymap.copy_mode`，可配置）toggle 进入：`enter()` 暂停 TUI 鼠标捕获 + `tmux_mouse::disable()` 关闭 tmux mouse 拦截，把原生拖拽选择交还终端模拟器（任意终端，不限 Kitty/WezTerm）；纯函数 `next_state` 契约（toggle 翻转/活跃吞键/Esc 退出，空转录也照进，chip 提供反馈）由 `handle_key` 带副作用执行；`is_active(copy_mode, shift_held)` 守卫 `Event::Mouse`；退出 `exit()` 恢复 TUI 鼠标捕获但 tmux mouse 保持 off。copy 模式期间 `render_clean` 以**无装饰全宽**渲染正文（去 body 圆角边框/滚动条列/`[turn cost]` 行/边框指示器；行内由 `clean.rs` 的 span 结构化净化取代文本启发式——`classify` 按 span 形状产出 `LineKind`（RoleHeader/PlanHeader/Rule/CodeTop/CodeBottom 纯装饰行整行丢弃；CodeRow 仅剥 `│ ` gutter、载荷逐字保留，代码块内 `---`/框线不误杀；Text 剥装饰槽与 `▎ ` 引言前缀，`▸` 工具头/`💭 Thinking` 等语义行保留），形状常量唯一真源为 markdown.rs 6 个 code/quote/rule 常量 + chat.rs 3 个角色/plan 头常量；净化行集由 `ViewportCache::cleaned()` 懒构建 `CleanModel`，滚动几何按净化行集计算），终端自带复制快捷键即得干净文本——app 自身不写剪贴板（app 内选区 `copy_select` 与 `osc52` 模块已删除，空转录 Empty flash 随之移除）。Shift-held 原生选择路径不变。`render_composer_clean`/`render_notepad_clean` 将净化整屏扩展到 composer 输入与 `/notepad` 编辑器（换行模型分别同源于 `composer::wrap_rows` 与 `notepad::editor::row_texts`），copy 激活期间 `render()` 不落硬件光标；软换行复制修复由 `copy_wrap.rs` 提供——`WrapPlan`（`Rc<RefCell>`，backend 与 renderer 共享，`active` 镜像 copy_mode、`soft` 每帧由 clean 渲染器重填）经 `render()` downcast 装配，`WrapAwareBackend` 的 `draw` 在软边界（末列非空符号 + 样式未变 + `plan.soft[y]`）抑制 `MoveTo` 让 DECAWM 标记 wrapped，硬换行/非 copy 帧与 plain backend 字节一致；toggle 为全局语义——plan-edit/notepad overlay 打开时照常生效（净化整屏由 `render_composer_clean`/`render_notepad_clean` 提供，notepad 净化视图末行自带 COPY MODE chip，因 render.rs 的共享 chip pass 早退于 notepad 全屏分支），Esc 先退 copy 模式、再关 overlay（分层模态）。
- `key_handler`（`src/key_handler.rs`）：`KeyAction` enum + `handle_key()` 分发器 + `move_hist()` 历史导航（↑ 新→旧召回、↓ 回空；Submit/Steer/Queue 三路提交均记录历史，运行中 Enter/Tab 提交经 app.rs 的 `push_history` 入史）。从 app.rs 提取（行数控制）。Ctrl+C/Ctrl+D 在 CONTROL 块同时匹配 `Char('c')|Char('d')` 和 Kitty 键盘协议下的原始控制字符 `Char('\u{3}')|Char('\u{4}')`——后者由 `DISAMBIGUATE_ESCAPE_CODES` 导致，不带 'c'/'d' 字面量。Ctrl+A/Ctrl+E = 光标跳首/尾（char 安全，与 Home/End 一致）。Alt+F/Alt+B = 单词前/后移（`composer::forward_word`/`backward_word`，readline 风格纯 char-index 运算；跳空白后按 `WordKind`（Word=字母数字_ / Punct / Space）同类消费，返回 `KeyAction::None` 不触发 turn）。`$` 在输入任意位置触发 skill picker（不再限空输入）；picker 选中插入 `$name ` token（带尾随空格，防止后续输入粘连 token 名）到光标，提交时由 `apply_skill_tokens` 解析；未过滤列表**尾部**「✕ clear」行 → `MenuOutcome::Clear` → `SetSkill(None)` → `apply_skill_selection` 以 `clear_skill:true` 落库（活跃 skill 的 TUI 手动清除路径，键入过滤时该行隐藏；skill 为 one-shot，run 结束通常已自动清除，此行用于提前/兜底清除）。
- **模式命令 admission**（`src/key_handler.rs`）：运行中文本 `/act`、`/plan`、`/act_clear_context` 仍可按 Enter 作为 steer、Tab 作为 queue，在安全边界应用；Shift+Tab 模式感知：act 下产出 `SwitchAgent("plan")`（非破坏纯切换、无倒计时守卫、草稿不动），plan 下产出 `ArmClearConfirm` 并把 composer 草稿作为复合尾部。`Ctrl+T` 产出 `KeyAction::SwitchAgent`，复用 `dispatch_mode_switch` 与 slash 入口的 running/subagent gate、持久化和状态反馈；busy 时保留 draft 并提示重试，不在半个 turn 中途切换。subagent 聚焦视图同样把 Ctrl+T 交给 app gate，而文本模式命令仍按子会话无模式语义处理。
- `app_helpers`（`src/app_helpers.rs`）：从 app.rs 提取的 `pub(crate)` 自由函数——`mk_input`/`start_turn`/`worker_dead`/`sys_tokens_for`/`push_history`/`push_user`/`data_dir_for`/`pre_key_intercept`/`handle_mouse`/`apply_skill_tokens`/`resolve_and_warn`/`apply_force_redraw`。`push_history` 只把输入记入方向键历史（重置 `hist_idx`）不回显 marker，`push_user` = `push_history` + `user:` marker 回显。经 `pub(crate) use crate::app_helpers::{...}` 在 app.rs 重导出，`crate::app::*` 测试引用路径不变。`start_turn` 返回 `bool`（`false` = 命令通道关闭 = worker 已死，调用方推 `[worker stopped]` marker + break）。`pre_key_intercept` 处理 Esc / Ctrl+L 退出 subagent 视图并回到底部跟随态（Ctrl+L 额外折叠所有 thinking / tool 输出 + 清空输入），Ctrl+F 经 out-param `needs_clear=true` 请求强制全屏重绘。`apply_force_redraw(needs_clear, terminal, &mut render_pending, &mut skip_next_render)`：`needs_clear=true` 时 `terminal.clear()` 抹除 diff buffer（下帧逐格重绘）并置位 `render_pending`、清 `skip_next_render`，`false` 严格 no-op。`handle_mouse` 处理全部鼠标事件（点击/拖拽/滚轮/选择）。`apply_skill_tokens` 解析内联 `$name` token 并激活 skill（写入 `skill_handle: Arc<Mutex<Option<String>>>` = `session.skill_prompt`）。`resolve_and_warn` 包装之并推未解析 skill 警告 marker。
- `skill_token`（`src/skill_token.rs`）：纯函数 `extract_skill_tokens(text) -> (String, Vec<String>)`——剥离**所有** `$name` token 返回干净文本 + 有序名称列表（仅用于发现/激活）；`strip_resolved_skill_tokens(text, resolved)`——只剥离已解析 token、unresolved 保留为字面量。零依赖、UTF-8 安全。`ChatView::collapse_all_collapsible()`（`src/chat.rs`）一键折叠所有 Thinking + Tool + Compaction 块（Ctrl+L 绑定）。
- `control_helpers`（`src/control_helpers.rs`）：idle 提交通用的控制命令判定（steer/queue 自 2026-08 P0 修复起原文入队/入 steer，不再本地剥 token）——`is_pure_control_cmd(clean)` 仅对**裸**控制命令（`/plan`、`/act`、`/act_clear_context`，无尾随参数）为真：此类纯模式切换不记录用户消息，故 app.rs 的 idle 提交路径**不**将其回显进 transcript（跳过 `push_user` 与 context 计数）；复合输入（`/plan `、`/plan fix it`）携带用户内容，**必须**在执行前回显（经 `QueueConsumed`/`SteerConsumed` 的 `text` 字段）。`forward_skill_if_compound(raw, clean)`：当 skill-token 剥离把复合命令（`/plan `→`/plan`）塌缩成裸命令时，回传原始 `raw` 让 runner 复合命令路径解析 skill 并注入触发词，否则原样返回 `clean`。
- `queue_admitter`（`src/queue_admitter.rs`）：Tab/Enter-while-running 队列提交的**离环 admit actor**——`admit_input` 走常驻任务串行 FIFO（`spawn_admitter(store)`），UI select 按键分支只做乐观上屏（负数 temp seq + `try_send`，零 `db_lock` 等待），完成经 `admit_done_rx` 分支对账（`idle_rekick::on_admit_done`）：temp 原位换真实 seq、seq 去重、`consumed` 台账（QueueConsumed 先到不复活）、失败删行 + flash + 恢复图片快照；**A1 滞留重启**——成功 admit 落库时若 UI 已 idle（runner 的 turn 恰好越过最后一次 pending 检查），复查 store 仍有 pending 行则以空 prompt 重启 drain（`idle_rekick` 模块），镜像 Done-handler 的 `drain_pending` 重启，杜绝"落库但永不消费"。动因：Store 单把 `db_lock` 在 turn 运行期被消息/事件/subagent flusher 与 `claim_next_queue` 持锁，内联 `.await` 会让整个事件循环（渲染+按键）停摆。配套守护：`queue_panel::plan` 对负数 seq no-op；`session_ui::snapshot` 不携带幻影行。`steer_fire`/`subagent_input` 的 Enter-steer 仍内联（同根因，后续同模式迁移）。`handle_queue`（含 Submit-running/Steer 路径同语义）：**原文**（`$name` token 保留）入队，skill 的解析/激活/落盘全部延迟到消费时刻（idle 边界 runner `record_compound`）——提交时急切解析会写与在跑 turn 共享的 `skill_prompt` Arc，使排队 `$skill` 立即生效（P0 缺陷）；TUI 本地 `active_skill/_body` 镜像在 `TurnDone` 后从 handle 重同步（name 由 `> Source:` 前缀派生，`skill_display::skill_name_from_body`）。
- `clear_confirm`（`src/clear_confirm.rs`）：plan 模式 Shift+Tab 与 `/act_clear_context`（legacy `/clear_context`）统一 arm 5s 倒计时；composer 在 armed 期间保持可编辑（chars/Backspace/Left/Right、Shift|Alt+Enter 换行照常，其余键吞掉），一次提交（Enter）立即执行——倒计时内键入的文本先并入复合尾部（`merge_typed`：重键入的 clear 命令其尾部取代 armed rest，普通文本追加），不必等满 5s；Esc 回撤并恢复草稿。fire 时 idle 直接开 control-command turn，running 则原文排队。真正的折叠与 agent 变迁由 session 决定：plan 下保留计划、切 act 并开始执行；act 下保留最后回复为中性接续种子；无 assistant 内容则空白开局。
- `theme`（`src/theme.rs`）：集中化颜色/样式层——单一真相源。10 个语义 `pub const Color`（ACCENT/WARN/OK/ERR/INFO/MUTED/SUBTLE/TEXT/LOCAL，16 色基线）+ Block 预设（`rounded_block_plain`/`rounded_block`/`rounded_block_focus`/`rounded_block_color`，均 `BorderType::Rounded`）+ `context_meter(pct)`（10 段 ▰/▱ ctx 用量仪表，阈值 >80 Red / >40 Yellow / else Green）+ `agent_chip_fg`/`status_chip_fg`（父状态条 chip 色：act 在 task-plan 提交态转 warn 黄，其余维持 agent 映射）/`list_highlight`/`bold`/`muted_style` 等。纯函数式 palette：单一固定 `const DARK: Palette`（无运行时切换状态），语义色函数 `accent()/text()/muted()/warn_color()/...`+`highlight_bg()` 直接返回其槽位，取值与 const 等价。render/chat/welcome/help/command/menu/task/queue_panel/model_menu/cache_salt_menu/subagent_input/local_cmd 引用 `crate::theme::*` 替换原内联硬编码；全部语义色（Cyan/Yellow/Green/Red/Blue/DarkGray/Gray/White/Magenta）已迁移 `theme::*()` 函数。仅保留 `Color::Black`（饱和背景前景字）、`Color::Rgb`/`Reset`/`Indexed`、model_menu Save/Cancel 按钮的 Green/Red bg 及 `status_label_color()` 的 `LightBlue`（状态栏 thr/ctx 标签，ANSI 94 固定亮蓝，BOLD）。
- `fmt`（`src/fmt.rs`）：紧凑数字/计时格式化纯函数（`format_tokens_compact`/`context_percent`/`format_run_duration`——后者被 `push_duration_span` 用于 Tool/Subagent 块表头计时渲染）。
- 共享滚动条（`src/scrollbar.rs`）：主体与 queue panel 共用纯函数 `thumb_geometry` 计算比例与端点；track/thumb 均使用带背景色的单空格单元格绘制，不依赖 `┊`/`█` 的字体 fallback 或 East Asian Ambiguous 宽度。滚轮处理器换行宽度 `r.width - 3` 与 render 的 `text_w = inner.width - 1` 对齐。
- **composer 与状态栏渲染**（`src/render.rs` + `src/render_status.rs`）：composer 支持显式换行、软换行、滚动与 Unicode 光标定位；底栏显示 agent chip、running 闪烁圆点、压缩阈值进度和 ctx%。`theme::status_chip_fg` 在 task-plan 激活时把 act chip 转为 warn 黄，其他状态按 agent 语义色；body 顶部标题为 `workdir · model · effort`，逐轮耗时显示在最新消息尾部而非状态栏。
- **running LLM-round `[turn cost]` 位于最新消息尾部**：`SessionEvent::LlmRoundStart` 在模型调用前设置当前 view 的 `llm_round_started_at_ms`，该 assistant 消息触发的全部 function call 完成后由 `LlmRoundEnd` 立即清空；`Done`/`Error`/subagent 终态也兜底清空。`app_display::display_tail_ms(chat, subagent_focus, now, running)` 只对当前 running 主任务或聚焦且未终态的 subagent 计算 live elapsed；轮间与终态返回 0，不冻结历史值。`render_body` 把 `[turn cost x]` 追加到当前最新非空内容行，放不下则独立换行；计时仅存在于事件/TUI 状态，不进入消息文本或模型 context。
- **plan-edit vim 引擎**（`src/vim/`，10 文件 ≤405 行/文件）：plan（只读）agent + idle + 空 composer 时 Shift+I 进入 plan 编辑，由独立 vim 子模块驱动——Normal/Insert/Command-line/Search 四模式；motions（`hjkl`/`wbe`/`0^$`/`G`/`gg`，带 count）；operators（`d`/`c`/`y` + count 与 motion 组合）；搜索（`/ ? n N`）；行操作（`x X o O J p P r D C`）；撤销/重做（`u`/`Ctrl+R`，插入会话整体算一次撤销）；`:q!`/`:q`/`:w`/`:wq`/`:x` 退出。`plan_edit.rs` 为薄适配器，对外保留 `PlanEdit`/`PlanEditAction`/`handle_plan_edit_key` 契约，内部委托 `VimState`，复用 `composer.rs` 的 wrapping/cursor 纯函数（`prompt_w=2`）。退出语义：`:q!`/`:q`/Ctrl+C 丢弃（恢复原文，`is_modified()`→false）；`:wq`/`:x`/Enter 保存保留。不含具名寄存器/宏/visual-block/`:%s`。
- **内联图片渲染**（`src/image_render.rs`）：`terminal_image_width()` 查询实时终端宽度并减去开销（缩进+边框=`IMAGE_WIDTH_OVERHEAD=8` 格），下限 20、headless 回退 120。缩放用 `image::imageops::FilterType::Triangle`。data URI 就地解码；HTTP(S) URL 经 `fetch_image_bytes` 预取。replay 逻辑位于 `session_ui/replay.rs`；Assistant 消息先把全部 `ContentBlock::Reasoning` 还原为 collapsed+sealed Thinking，再把所有 Text 合成唯一 Assistant，保证 resume/compaction 与 live 同为 Thinking → Say 顺序。

## 主流程

命令弹窗内输入命令名后，Space/Tab 都会把当前选中的规范 slash 命令及尾随空格填回 composer 并关闭弹窗；因此可直接继续输入 `/plan <需求>`，无匹配项时 Space 保持弹窗和查询不变。

`run_app` loop：每帧 `render()`（受 `skip_next_render` 门控——折叠态 `ReasoningDelta` 跳过全量重绘，300ms anim_ticker 仍周期刷新）→ `tokio::select!`（终端事件 `input_rx` / 离环 admit 完成 `admit_done_rx`（`if admitter_alive` 防 closed-channel 忙转）/ worker `evt_rx` / anim ticker）。select 带 `biased;`——臂按声明顺序优先 poll（输入臂在前），键盘/鼠标 steer 中断不被随机化顺序延迟。**输入采集**（`src/input.rs`）：专用 OS 线程跑同步有界 `crossterm::event::poll(150ms)`+`read()`，经 tokio mpsc `blocking_send` 投递到 `input_rx`——弃用 `EventStream`（其 async reader 任务走 mio + tokio waker，一旦停滞 `select!` 输入臂永不触发，整循环冻死、Ctrl+C/D 全失效）；改走同步路径绕过 async reader 停滞这一失败模式（crossterm unix source 用 `filedescriptor::poll`+非阻塞读，有界；`poll` 成功后 `read()` 从内部队列弹已入队事件，不触及 `poll(None)` 回退）。receiver drop（`is_closed()`）即令线程退出。**Esc 尾部守卫**（`EscGuard`）：tmux/pty 可把转义序列拆写到两次 write（Esc 一次、`[D` 下一次），crossterm 0.28 会把孤立 `\x1b` 立即提交为 Esc 键、把孤儿尾当普通字符打进输入框成 `[D`/`[A` 垃圾。守卫以纯函数 `esc_guard_feed(state, expired, ev)` 三态状态机（`Idle`/`Holding`/`SwallowTail`）在 `ESC_GUARD_WINDOW=80ms`（neovim `ttimeoutlen` 同量级）窗口内重组分裂序列：单独 Esc 保留（窗口到期提交）、Esc 双击=两次原样放行（保 cancel）、Esc+`[`/`O`=进入 SwallowTail 吞掉 CSI/SS3 残尾字节（字母数字/`;~<>?`）、Esc+普通键=双双放行；pump 经 `EscGuard::poll_timeout` 在 deadline 提前唤醒，无额外可见延迟，逻辑零时钟纯函数可表驱动测试。**终端生命周期**（`src/terminal.rs`）：`TerminalGuard` RAII（`run()` 持有）——enter 开 raw+alt-screen+鼠标+Kitty 并装 panic hook（panic 时先恢复终端再打印），Drop 幂等恢复；任何退出路径（正常/`?`错误/panic unwind）都恢复终端，不再"变砖"。**启动 clear**（`app_bootstrap.rs`）：`TerminalGuard::enter` 后、首帧前对 `Terminal` 立即 `clear()`（ESC[2J + diff baseline 重置）——进入 alt screen 本身**不**清屏，tmux 每 pane 保留一块持久 alt-screen grid，上一轮运行的末帧（含状态栏隐藏/`""`）会透过首帧 diff 的空格空洞（empty-vs-empty 永不重写）可见；真 clear 使首帧全量重绘，与 `resume_screen` 的 clear-after-reenter 契约一致。**未知 `--session <id>` 解析**（`app_bootstrap.rs`）：传入的 id 既不在 store、也不是 subagent task 时，不再报 "session not found"——改为建一个带 `.ts_origin()` 的全新 `SessionState`（tmux 启动路径：`ts_start` 仅分配 id、不预置 DB 行，会话行惰性由首条 `record()` 落库）。`input_rx.recv()` 返回 `None`（采集线程退出/stdin EOF）时 `UiCmd::Quit` + break。**活性监管**（`src/supervisor.rs`）：tty 死亡（SSH 断连 / tmux kill / 关终端——tty 返 回 `Ok(0)`/`EIO`）时 crossterm 0.28 的 mio `try_read` 永久忙循环、持有全局事件互斥锁，连同步 `poll` 也会卡死。supervisor 在专用 OS 线程（不依赖 tokio / 不受该锁影响）上每 1s 读输入泵心跳（`AtomicU64` ms-epoch，每次 `poll` 前 bump）；心跳 stale > 5s 或收到 SIGHUP/INT/QUIT/TERM 即 `TerminalGuard::restore()` + `exit(0)`。`run_app` 正常退出前 `supervisor_active.store(false)` disarm。

**tmux resize clear**（`src/resize.rs`）：显式 `Resize` 事件与每帧尺寸轮询发现变化时，统一执行 `autoresize()` + `clear()`。ratatui 会把 pane 扩展后的新单元格视为空白、不产生 diff，真 clear 同时清掉 tmux 持久的物理 grid 并重置 diff baseline，防止隐藏状态栏或 pane 缩放后信息区旧字符透出。清屏/尺寸 I/O 失败直接上报，不以部分刷新状态继续。

**终端帧契约**（`src/frame.rs` + `src/render.rs`）：所有环境统一使用 ratatui `Terminal<CrosstermBackend<Stdout>>` 的增量 diff；应用不再发送 DECSET 2026、不再在 tmux 内逐帧废弃 diff baseline，也不再给每个 cell 注入绝对光标移动。tmux 自己维护 pane grid 并负责 tmux→client 的差分输出，应用侧扩大为完整帧或逐 cell 定位既不能约束该下游链路，反而会把每次动画 tick 放大为整屏输出并触发 tmux/iTerm2 闪屏。启动、resume 与真实 resize 仍执行一次生命周期 clear，用户显式 force-redraw 仍可单次 clear；稳态帧绝不 clear，只输出实际变化和用于擦除缩短内容的空格。共享滚动条继续使用背景色空格，避免字体 fallback。Unicode 内容保持原样；外层终端必须与 tmux 使用一致的 Unicode 宽度规则（iTerm2 关闭 ambiguous double-width，并启用 Unicode 9+ widths）。

- **render**：`display_chat` / `display_title` / `display_ctx` / `display_sys` = subagent_focus 时取子 ChatView 及其 `context_used` + 缓存的 `subagent_sys`（进入时 `sys_tokens_for(kind, workdir, None)` 算一次），否则取 `&chat` + `chat.context_used` / `sys_tokens`。`display_agent` = focus 时 `← [Ctrl+L] back | ⇲sub [kind] prompt`。
- **Session 事件**：`chat.apply(&sev)` 内部调 `track_context` 更新当前 view；SubagentChild 路由到子 ChatView。TranscriptReset/resume 经 `session_ui::replay_into_chat` 重建并回填 `context_used`。worker 为每条命令创建单一有序异步转发器连接同步 LLM callback 与有界 UI mpsc：接近满时只允许丢弃顶层 `TextDelta`，SubagentChild delta、ReasoningDelta、TranscriptReset 与生命周期事件均按原序等待容量；同一队列随后投递 `UiEvent::AssistantFinal` 完成态和 `TurnDone`。`reconcile_completed_assistant` 在 `turn_block_start` 之后校准或补建唯一 Say，即使全部父级正文 delta 被丢也不缺字、不覆盖旧轮；`TurnDone` 可靠收口 agent、markdown 与孤儿 subagent 状态。
- **subagent ctx 切换**：`subagent_focus: Option<usize>` 状态。进入时 `scroll=0; follow=true`（不保存 parent 滚动状态），退出（Esc 或 Ctrl+L，均在 `pre_key_intercept` 优先拦截）统一回到底部跟随态。
- **输入模式**：Enter = steer（running）/ submit（idle），Tab = followup（running）/ submit（idle），Ctrl+T = 保留上下文与 draft 的 act↔plan 纯切换，Shift+Tab = act 下切 plan（保留上下文与 draft 的非破坏纯切换，空闲边界生效）、plan 下受倒计时保护的 plan→act 执行交接。Ctrl+T 与 `/act`、`/plan` 共享 `dispatch_mode_switch`；Shift+Tab 与键入 `/act_clear_context` 共享 `clear_confirm`。running 或 live subagent 时直接切换键被 busy gate 拦截，不改变 sys_tokens/input/agent；文本命令仍可通过 queue/steer 延迟到边界。Alt 字符守卫继续阻止 tmux 分裂转义序列污染输入。
- **子代理 steer 提交结果**：`subagent_input::admit_subagent_steer` 必须先从 `child_steer_gates` 取得 live reservation。成功才清空 composer 图片并向子 view 增加 pending 行；若 child 已越过终止边界，恢复输入文字、保留图片并显示 `subagent already finished — steer not submitted`；store 错误直接显示且同样保留输入。Enter 仍等待自然 turn 边界，`>` 仍只负责立即触发目标 child 的 turn cancel。
- **中止与续跑**：双击 Esc 硬中止（`KeyAction::Cancel` → `cancel.cancel()`，`run_app` 即刻 `running=false`）。每个新 turn 由 `start_turn` 先发 `UiCmd::ResetCancel(新 token)` 再发工作命令（mpsc FIFO，4 个派发点：Submit idle / 模式控制命令 `/act`、`/plan`、`/act_clear_context` / Compact / TurnDone 续跑），刷新 worker 的 `sess.cancel`——否则 token 永久取消会使 `run_loop` 顶部 `is_cancelled()` 永真、后续提交被静默丢弃。`start_turn` 返回 `bool`：`false` = 命令通道关闭（worker 已死，panic 或意外退出），派发点收到 `false` 时 `worker_dead()` 推 `[worker stopped]` marker 并 break。输入采集在独立 OS 线程，worker 死后 UI 仍响应 Ctrl+C/D，用户可干净退出而非面对冻死 spinner。
- **`/ap` autopilot 模式菜单**（`ap_menu/`：`list.rs`/`state.rs`/`view.rs`，持久化接线 `app_loop_ap.rs`）：三选项 `off（无自动行为）/ ap（完全自动 PLAN→ACT→VERIFY）/ review（自动 review，一次性）`，`new(config)` 高亮当前 `config.autopilot.mode`；↑/↓ 移动、Enter 选择即以 `{"autopilot":{"mode":..}}` merge-patch 保存 + reload + `UiCmd::ReloadConfig`（chat 内 `[ap] autopilot mode: <mode>` 标记，失败红字）、Esc/Ctrl-D 取消关闭。composer 右上 chip：ap→`AP`、review→`RV`、off→无（取代旧 `/ap` 一键翻转布尔开关）。
- **`/skill` 默认注入开关弹窗**（`skill_menu/`：`list.rs`/`state.rs`/`view.rs`，别名 `/sk`，持久化接线 `app_loop_skill.rs`）：与 `/cli` / `/mcp` 同型的开关列表——发现结果合并 config 开关（缺省 OFF），`←/→` 翻转选中项并立即以 JSON merge-patch 保存 + reload + `UiCmd::ReloadConfig`，chat 内打 `[/skill] saved → <path>` 标记（失败红字 marker）；Enter/Esc 关闭（Ctrl-D 兜底强关）。ON 的 skill 进入 context 尾部 `[skills]` 目录提醒（目录+名称+概要，模型按需读 SKILL.md）。
- **`/envs` 环境配置管理弹窗**（`envs_menu/`：`list.rs`/`form.rs`/`state.rs`/`view.rs`，别名 `/env`，接线 `app_loop_envs.rs`）：List 页 `EnvsMenu::List`——BASE_ROW=0（无选中环境行，显式 None）+ 各环境行，↑/↓ 导航（含 BASE 行）、Enter 激活选中环境 / 在 BASE 行去激活、`n` 新建（开 Form）、`e` 重捕获选中、`d` 删除（y/N 二步确认）、Esc/Ctrl-D 取消；Form 页 `EnvsMenu::Form`——名字输入实时合法性校验（非法/重名阻断提交）、空格切换 capture 开关、粘贴支持、Enter 创建、Esc 返回 List。`EnvsOutcome` 七态（Idle/Activate/Deactivate/Create/Recapture/Delete/Cancel）由 `handle_envs_outcome` 分发；激活/去激活/删除/重捕获后 `refresh_after_env_change` 镜像 `/model` 的重建流程（`resolve_endpoint` 重建 client、model_label 刷新、fps ticker、`UiCmd::ReloadConfig` 通知 worker）。
- **集成注册弹窗**：`/cli`（`cli_menu/`）管理 `{name,enabled,inject_to,content}` CLI 注册；`/mcp`（`mcp_menu/`）管理 server transport，并同样提供 `inject_to` 多选。两者列表以 `←/→` 启停；聚焦 InjectTo 字段按 Enter/Space 弹出共享勾选对话框（`scope_dialog/`：↑/↓ 移动、Space 勾选、Enter 确认——空选不可确认、Esc 取消，对话框打开时粘贴被吞掉）；`/cli` 的 Content 字段按 Enter 弹出多行编辑器（`cli_menu/content_dialog.rs`：Enter 换行、Ctrl+S 应用回写、Esc 取消、Ctrl+U 清空、滚动跟随光标，粘贴原样插入含换行，折叠字段保留单行预览）。支持增删改；保存 JSON merge-patch 后 reload `Config` 并派发 `UiCmd::ReloadConfig`，下一模型调用生效。
- **弹窗锚点**：`/` 命令面板（`command.rs`）与 `/config`/`/model` 配置（`model_menu/`）以 composer 顶边 `y` 为底锚渲染下拉浮层（非屏幕居中）。**`/config`**（`ConfigForm`）= 生成参数表单（reasoning 四档循环 / interleave 开关 / max_tokens / ctx size(context_limit) / context_threshold / fps；Save 时校验 context_threshold ≤ ctx size，越界阻断保存），文本字段（max_tokens/ctx size/threshold/fps/ap_max_iter）聚焦时经 `view.rs` 的 `text_field_row`+`focused_raw_input` 在原始数字输入末尾 `set_cursor_position`（非文本字段/按钮不定位、光标隐藏）；`render.rs` 输入框 `place_cursor` 以 `model_menu.is_none()` 门控避免与模态光标冲突，Enter 推进字段到 `[Save]` 提交；**`/model`**（`model_menu/`：`ProviderList` + `ProviderForm`）= Provider CRUD：列表 Enter 进入两步确认态 `confirm_save_default`（浮层标题 `SAVE AS DEFAULT? y=global, n/Enter=session-only`）——`y`/`Y` → `ModelOutcome::Save`（`Config::save` 写回 opencoder.json）；`n`/`N`/Enter/Esc → `ModelOutcome::SaveSessionOnly`（**默认 session-only**：merge-patch 只进内存 config + 重建外层 client，经 `model_session_switch::switch_session` 派发 `ReloadConfig` 让 worker 写进 session store 行，**不写盘**；resume 即生效）；`e`=编辑 / `n`=新建 / `d`=删除（y/n 两步确认）。编辑表单含 name/model_id/base_url/api_key（掩码+重输）/自定义 headers 子编辑器（`HeadersEditor`：`+`/`-` 增删 pair，`←/→` name↔value），提交产出的 JSON merge-patch 同样经 Save/SaveSessionOnly 两分支决定是否落盘。question 对话框（`question_menu/`）：同轮并行的 `ToolStart{name=="question"}` 聚合进一个 composer 顶边锚定表单，`←/→` 切题、`↑/↓` 选预设或 Custom、Tab 聚焦每题独立保留的下方输入框；预设可追加输入（结果为 `预设\n输入`），Custom 仅提交输入。Enter 逐题确认且可切回修改，全部确认后才按原 tool-call 顺序批量 `QuestionHub::resolve`，使下一轮 context 同时获得所有答案；Esc/Ctrl+D 将当前题确认为跳过。预设值仅在渲染时显示 `1. `、`2. ` 序号，Custom 不编号，context 仍接收原始值。输入框固定锚定在弹窗底部，高度随软换行动态增长（cap 6 内容行，超出内部滚动），wrap 宽度公式由 `question_menu::input_wrap_width` 单源供按键/渲染两侧共享，光标以输入框内矩形和 Unicode 显示宽度定位，不受问题/选项换行影响；输入框支持 readline 快捷键（Ctrl+A/E/U/K/W、Alt+B/F/Backspace、Home/End/Delete、Shift+Enter/Ctrl+J 换行、多行粘贴），Up/Down 在视觉行间移动（首行 Up 才回选项区）；选项高亮随 `selected` 不随焦点（焦点由 Input 边框色表达）；`ToolEnd` cancel 与 `/task` 切换均 abandon 全部未回填问题。
`/task` 会话选择器（`task.rs`）为屏幕居中模态：`+ New task` + 历史 session 列表（当前会话标 `(current)`），底部红色 `✕ Clear all N task(s)` destructive 行——选中 Enter 进入红色两步确认态（再 Enter 触发 `TaskOutcome::ClearAll`；app 层经 `gate_clear_all(running)` 守卫：`running==true` 即 turn/subagent 飞行中时拒绝并推黄色 busy marker，idle 后才调 `Store::clear_other_sessions` 删除除当前会话外的全部会话并刷新列表；Esc 取消确认、确认态锁定 ↑/↓、Ctrl+C/D 仍即时退出）。
