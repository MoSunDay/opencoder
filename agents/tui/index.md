# tui 模块

## 职责
ratatui + crossterm 交互界面。3-region 布局、事件循环、鼠标命中测试、键盘分发、subagent 可折叠 + ctx 切换。

## 边界与非目标
- 不直接调 Store CRUD（经 worker `UiCmd` 通道）；不持有 SessionState（worker 持有）。
- 非目标：TUI 不是 Web 替代品——app 内无 SSE replay，仅 live event 流；但 **worker 持有 `Option<Arc<dyn Store>>`**，每个 SessionEvent 经 `worker::persist_event`（fire-and-forget spawn）写入 `session_events`（含 `sse_kind`），故 web/SSE 客户端可回放 TUI 驱动的会话（TUI 自身不在 app 内回放）。

## 关键抽象
- `ChatView`（`src/chat.rs`）：`blocks: Vec<ChatBlock>` + `agent/status/subagents_running/subagents_total/context_used`。`apply(&SessionEvent)` 逐事件更新——核心接缝；内部 `track_context` 只累加本 view transcript token（不递归 SubagentChild——父 view 的 context_used 仅含自身，子 view 独立维护自身子树）。app.rs 不再有独立 `context_used` 变量——直接读写 `chat.context_used`。 `last_thinking_collapsed()` 返回末尾块是否为折叠 Thinking——供 app.rs 在 `ReasoningDelta` 流式写入时跳过逐 delta 全量重绘（折叠态无可见变化，300ms anim_ticker 仍周期刷新 spinner + 行数计数）。
- `ChatBlock`（`src/chat.rs`）：`Marker(Vec<Line>)` / `Assistant{raw,rendered,done}` / `Thinking{text,collapsed}` / `Tool{header,output}` / `Subagent{id,child_session_id,kind,prompt,view:ChatView,done,ok,summary}`。`flatten()` → `Vec<Line>` 供 Paragraph 渲染。
- `Subagent` block 不可内联展开：始终单行表头 `⇲ subagent [kind] prompt [●/✔/✘ status, N tools] [→ view]`（running=黄● / done=绿✔ / failed=红✘）。点击表头直接进入子会话 ctx 视图（body 渲染子 ChatView + 子 view 自有 context_used 驱动状态栏 ctx 仪表），Esc / Ctrl+L 返回主进程并回到底部跟随态。
- `MouseHits`（`src/render.rs`）：每帧重算的命中目标——`jump_btn/body/queue_btns/thinking_btns/subagent_btns/tool_btns/compaction_btns`。`record_thinking_hits` / `record_subagent_hits` / `record_tool_hits` / `record_compaction_hits` 映射逻辑行号到屏幕行号（含视口裁剪：滚出可见区不计）。Compaction 块与 Thinking 块共用 `render_collapsible`（`compaction_block.rs`），现已接入同一 click-to-expand hit-rect 管线——点击表头行经 `handle_mouse` → `toggle_compaction_at` 翻转折叠态；折叠 header 显 `{icon} {label} ({N} lines)` 行数摘要，展开 header 仅显 `{icon} {label}`（均无 expand-collapse 提示文字）。 Compaction 块现**流式展开**：`CompactionDelta` 经 `open_compaction_streaming`（`compaction_block.rs`）追加进 `streaming=true` 的展开块——用户在 summary LLM 调用期间即见生成文字；最终 `Compaction(summary)` 事件经 `finalize_compaction` 覆写全文并折叠（`streaming=false`）。故 `CompactionDelta` 不再属可丢弃 delta（`worker::is_droppable_delta`）。
- `key_handler`（`src/key_handler.rs`）：`KeyAction` enum + `handle_key()` 分发器 + `move_hist()` 历史导航。从 app.rs 提取（行数控制）。Ctrl+C/Ctrl+D 在 CONTROL 块同时匹配 `Char('c')|Char('d')` 和 Kitty 键盘协议下的原始控制字符 `Char('\u{3}')|Char('\u{4}')`——后者由 `DISAMBIGUATE_ESCAPE_CODES` 导致，不带 'c'/'d' 字面量。Ctrl+A/Ctrl+E = 光标跳首/尾（char 安全，与 Home/End 一致）。Alt+F/Alt+B = 单词前/后移（`composer::forward_word`/`backward_word`，readline 风格纯 char-index 运算；跳空白后按 `WordKind`（Word=字母数字_ / Punct / Space）同类消费，返回 `KeyAction::None` 不触发 turn）。`$` 在输入任意位置触发 skill picker（不再限空输入）；picker 选中插入 `$name ` token（带尾随空格，防止后续输入粘连 token 名）到光标，提交时由 `apply_skill_tokens` 解析。
- `app_helpers`（`src/app_helpers.rs`）：从 app.rs 提取的 `pub(crate)` 自由函数——`mk_input`/`start_turn`/`worker_dead`/`sys_tokens_for`/`push_user`/`data_dir_for`/`pre_key_intercept`/`handle_mouse`/`apply_skill_tokens`/`resolve_and_warn`/`apply_force_redraw`。经 `pub(crate) use crate::app_helpers::{...}` 在 app.rs 重导出，`crate::app::*` 测试引用路径不变。`start_turn` 返回 `bool`（`false` = 命令通道关闭 = worker 已死，调用方推 `[worker stopped]` marker + break）。`pre_key_intercept` 处理 Esc / Ctrl+L 退出 subagent 视图并回到底部跟随态（Ctrl+L 额外折叠所有 thinking / tool 输出 + 清空输入），Ctrl+F 经 out-param `needs_clear=true` 请求强制全屏重绘。`apply_force_redraw(needs_clear, terminal, &mut render_pending, &mut skip_next_render)`：`needs_clear=true` 时 `terminal.clear()` 抹除 diff buffer（下帧逐格重绘）并置位 `render_pending`、清 `skip_next_render`，`false` 严格 no-op。`handle_mouse` 处理全部鼠标事件（点击/拖拽/滚轮/选择）。`apply_skill_tokens` 解析内联 `$name` token 并激活 skill（写入 `skill_handle: Arc<Mutex<Option<String>>>` = `session.skill_prompt`）。`resolve_and_warn` 包装之并推未解析 skill 警告 marker。
- `skill_token`（`src/skill_token.rs`）：纯函数 `extract_skill_tokens(text) -> (String, Vec<String>)`——剥离**所有** `$name` token 返回干净文本 + 有序名称列表（仅用于发现/激活）；`strip_resolved_skill_tokens(text, resolved)`——只剥离已解析 token、unresolved 保留为字面量。零依赖、UTF-8 安全。`ChatView::collapse_all_collapsible()`（`src/chat.rs`）一键折叠所有 Thinking + Tool + Compaction 块（Ctrl+L 绑定）。
- `theme`（`src/theme.rs`）：集中化颜色/样式层——单一真相源。10 个语义 `pub const Color`（ACCENT/WARN/OK/ERR/INFO/MUTED/SUBTLE/TEXT/LOCAL，16 色基线）+ Block 预设（`rounded_block_plain`/`rounded_block`/`rounded_block_focus`/`rounded_block_color`，均 `BorderType::Rounded`）+ `context_meter(pct)`（10 段 ▰/▱ ctx 用量仪表，阈值 ≥85 Red / ≥60 Yellow / else Green，与原 `render_status` 内联逻辑一致）+ `agent_chip_fg`/`list_highlight`/`bold`/`muted_style` 等。纯函数式 palette（dark/light 两套 `palette(kind)`）；运行时经全局 `ThemeKind`（`OnceLock<RwLock>`，`set_theme`/`current_theme`，默认 dark）驱动语义色函数 `accent()/text()/muted()/warn_color()/...`+`highlight_bg()`——`/config` 表单切换并持久化（`Config.theme`），dark 下与 const 等价、light 为白底可读 palette。render/chat/welcome/help/command/menu/task/queue_panel/model_menu/cache_salt_menu/subagent_input/local_cmd 引用 `crate::theme::*` 替换原内联硬编码；全部语义色（Cyan/Yellow/Green/Red/Blue/DarkGray/Gray/White/Magenta）已迁移 `theme::*()` 函数——切换 light 即全局生效。仅保留 `Color::Black`（饱和背景前景字）、`Color::Rgb`/`Reset`/`Indexed` 及 model_menu Save/Cancel 按钮的 Green/Red bg（两主题取值相同）。
- `selection`（`src/selection.rs`）+ `clip_probe`（`src/clip_probe.rs`）：鼠标拖拽文本选择 + 剪贴板复制。选择以绝对内容行 `[a,b]`（`screen_row + scroll`）追踪——滚动时锚定文本不漂移；松开鼠标 `finish_copy` 提取选中逻辑行经 `copy_osc52`（vendored base64 + `ESC]52;c;` 序列）+ 本地命令写入系统剪贴板。**clip_probe** 探测终端类型（VTE/screen→OSC52 不可靠）、显示服务器（Wayland/X11/headless→智能分派 wl-copy/xclip/xsel）、SSH（跳过本地命令）；`OnceLock` 缓存探测结果。`CopyReport` 诚实反馈：`osc52_reliable` + `local_tool` → 可靠时绿色成功，不可靠+无本地工具时红色失败+安装指引。`render_overlay` 在 Paragraph 之上叠反白高亮（fg/bg 互换）。测试文件拆分（`#[path]` include）：`app.rs`→`app_tests/mod.rs`（+ `key_tests`/`skill_tests` 子模块）、`app_helpers.rs`→`app_helpers_tests/mod.rs`（+ `mouse_tests`/`mouse_clip_tests`/`skill_apply` 子模块）、`chat.rs`→`chat_tests.rs` + `subagent_tests.rs`、`render.rs`→`render_tests.rs`，各经 `#[cfg(test)] #[path = "..."] mod tests;` 引入——模块路径不变（`app::tests`/`app_helpers::tests`/`chat::tests`/`chat::subagent_tests`/`render::tests`），仅为控制单文件 ≤800 行迭代上限，不影响公开 API。

## 主流程
`run_app` loop：每帧 `render()`（受 `skip_next_render` 门控——折叠态 `ReasoningDelta` 跳过全量重绘，300ms anim_ticker 仍周期刷新）→ `tokio::select!` 三臂（终端事件 `input_rx` / worker `evt_rx` / anim ticker）。select 带 `biased;`——三臂按声明顺序优先 poll（输入臂在前），键盘/鼠标 steer 中断不被随机化顺序延迟。**输入采集**（`src/input.rs`）：专用 OS 线程跑同步有界 `crossterm::event::poll(150ms)`+`read()`，经 tokio mpsc `blocking_send` 投递到 `input_rx`——弃用 `EventStream`（其 async reader 任务走 mio + tokio waker，一旦停滞 `select!` 输入臂永不触发，整循环冻死、Ctrl+C/D 全失效）；改走同步路径绕过 async reader 停滞这一失败模式（crossterm unix source 用 `filedescriptor::poll`+非阻塞读，有界；`poll` 成功后 `read()` 从内部队列弹已入队事件，不触及 `poll(None)` 回退）。receiver drop（`is_closed()`）即令线程退出。**终端生命周期**（`src/terminal.rs`）：`TerminalGuard` RAII（`run()` 持有）——enter 开 raw+alt-screen+鼠标+Kitty 并装 panic hook（panic 时先恢复终端再打印），Drop 幂等恢复；任何退出路径（正常/`?`错误/panic unwind）都恢复终端，不再"变砖"。`input_rx.recv()` 返回 `None`（采集线程退出/stdin EOF）时 `UiCmd::Quit` + break。**活性监管**（`src/supervisor.rs`）：tty 死亡（SSH 断连 / tmux kill / 关终端——tty 返 回 `Ok(0)`/`EIO`）时 crossterm 0.28 的 mio `try_read` 永久忙循环、持有全局事件互斥锁，连同步 `poll` 也会卡死。supervisor 在专用 OS 线程（不依赖 tokio / 不受该锁影响）上每 1s 读输入泵心跳（`AtomicU64` ms-epoch，每次 `poll` 前 bump）；心跳 stale > 5s 或收到 SIGHUP/INT/QUIT/TERM 即 `TerminalGuard::restore()` + `exit(0)`。`run_app` 正常退出前 `supervisor_active.store(false)` disarm。

- **render**：`display_chat` / `display_agent` / `display_ctx` / `display_sys` = subagent_focus 时取子 ChatView 及其 `context_used` + 缓存的 `subagent_sys`（进入时 `sys_tokens_for(kind, workdir, None)` 算一次），否则取 `&chat` + `chat.context_used` / `sys_tokens`。`display_agent` = focus 时 `← [Ctrl+L] back | ⇲sub [kind] prompt`。
- **Session 事件**：`chat.apply(&sev)` 内部调 `track_context` 更新 `chat.context_used`（只计本 view token，SubagentChild 不计入父），SubagentChild 路由到子 block view（子 view 的 apply 独立更新自身 context_used）；TranscriptReset / resume 经 `session_ui::replay_into_chat` 重建 ChatView——返回前以 `estimate_messages(messages)` 一次性回填 `context_used`（含摘要+保留尾部，与压缩路径同源减去 system），故重建后 ctx% 反映真实流水账而非归零。 worker→UI 转发经 `forward_event(&tx, sev)`（`src/worker.rs`）而非裸 `try_send`：有界 mpsc 接近满（`tx.capacity() <= DELTA_MIN_CAPACITY=64`）时丢弃可恢复的流式 delta（`TextDelta`/`ReasoningDelta`/包裹它们的 `SubagentChild`）；最终文本总在 `TurnDone → finalize_assistant()` 从 store 重建，故无数据丢失；生命周期事件（TurnDone/Error 等）始终 `try_send` 优先占槽。
- **subagent ctx 切换**：`subagent_focus: Option<usize>` 状态。进入时 `scroll=0; follow=true`（不保存 parent 滚动状态），退出（Esc 或 Ctrl+L，均在 `pre_key_intercept` 优先拦截）统一回到底部跟随态。
- **输入模式**：Enter = steer（运行中）/ submit（idle）；Tab = followup（运行中）/ submit（idle）；Shift+Tab 切 plan/act（触发 plan→act handoff，清空 transcript 只留最终计划）；**`/act`、`/act_clear_context`** 在 plan 模式且已提交计划（`plan_submitted` + idle）时同走 `SwitchAndStart` 交接（保留计划并自动执行，与 Shift+Tab 同路径），否则仍 dispatch 控制命令（act 模式下 `/act` 切换、`/act_clear_context` 清空 transcript）；**t+Tab** 切 plan/act 但**不清空** transcript（`KeyAction::SwitchAgentNoClear`——输入框恰为 `t` 时按 Tab，保留完整上下文）。
- **中止与续跑**：双击 Esc 硬中止（`KeyAction::Cancel` → `cancel.cancel()`，`run_app` 即刻 `running=false`）。每个新 turn 由 `start_turn` 先发 `UiCmd::ResetCancel(新 token)` 再发工作命令（mpsc FIFO，4 个派发点：Submit idle / SwitchAndStart / Compact / TurnDone 续跑），刷新 worker 的 `sess.cancel`——否则 token 永久取消会使 `run_loop` 顶部 `is_cancelled()` 永真、后续提交被静默丢弃。`start_turn` 返回 `bool`：`false` = 命令通道关闭（worker 已死，panic 或意外退出），派发点收到 `false` 时 `worker_dead()` 推 `[worker stopped]` marker 并 break。输入采集在独立 OS 线程，worker 死后 UI 仍响应 Ctrl+C/D，用户可干净退出而非面对冻死 spinner。
- **弹窗锚点**：`/` 命令面板（`command.rs`）与 `/config`/`/model` 配置（`model_menu/`）以 composer 顶边 `y` 为底锚渲染下拉浮层（非屏幕居中）。**`/config`**（`ConfigForm`）= 生成参数表单（reasoning 四档循环 / interleave 开关 / max_tokens / ctx size(context_limit) / context_threshold / fps / capabilities 开关；Save 时校验 context_threshold ≤ ctx size，越界阻断保存），文本字段（max_tokens/ctx size/threshold/fps/ap_max_iter）聚焦时经 `view.rs` 的 `text_field_row`+`focused_raw_input` 在原始数字输入末尾 `set_cursor_position`（非文本字段/按钮不定位、光标隐藏）；`render.rs` 输入框 `place_cursor` 以 `model_menu.is_none()` 门控避免与模态光标冲突，Enter 推进字段到 `[Save]` 提交；**`/model`**（`model_menu/`：`ProviderList` + `ProviderForm`）= Provider CRUD：列表 Enter 进入两步确认态 `confirm_save_default`（浮层标题 `SAVE AS DEFAULT? y=global, n/Enter=session-only`）——`y`/`Y` → `ModelOutcome::Save`（`Config::save` 写回 opencoder.json）；`n`/`N`/Enter/Esc → `ModelOutcome::SaveSessionOnly`（**默认 session-only**：merge-patch 只进内存 config + 重建外层 client，经 `model_session_switch::switch_session` 派发 `ReloadConfig` 让 worker 写进 session store 行，**不写盘**；resume 即生效）；`e`=编辑 / `n`=新建 / `d`=删除（y/n 两步确认）。编辑表单含 name/model_id/base_url/api_key（掩码+重输）/自定义 headers 子编辑器（`HeadersEditor`：`+`/`-` 增删 pair，`←/→` name↔value），提交产出的 JSON merge-patch 同样经 Save/SaveSessionOnly 两分支决定是否落盘。`/task` 会话选择器（`task.rs`）为屏幕居中模态：`+ New task` + 历史 session 列表（当前会话标 `(current)`），底部红色 `✕ Clear all N task(s)` destructive 行——选中 Enter 进入红色两步确认态（再 Enter 触发 `TaskOutcome::ClearAll`；app 层经 `gate_clear_all(running)` 守卫：`running==true` 即 turn/subagent 飞行中时拒绝并推黄色 busy marker，idle 后才调 `Store::clear_other_sessions` 删除除当前会话外的全部会话并刷新列表；Esc 取消确认、确认态锁定 ↑/↓、Ctrl+C/D 仍即时退出）。
- **`/install_tools` 命令**（`install_tools.rs` + `core::tool_deps`）：命令面板（`SlashAction::InstallTools`）经 `LoopFlow::InstallTools` 上抛至 `app.rs`（需 terminal 句柄，`dispatch_command` 不持有之），`install_tools::run(terminal, &mut chat)` 用 `opencoder_core::check_tool_deps()` 探测 tmux/chromium/sentinel——全装则推绿色 no-op marker 返回；缺则 `terminal::suspend_screen()`（关 raw mode + 退出 alt screen）后以继承 stdio 跑 `install-skills-dep.sh`（用户可输 sudo 密码），`resume_screen()` + `Terminal::clear()` 全屏重绘、重种子 dep-gated skill（ssh-pty/chrome-headless），推格式化结果 marker。`terminal::suspend_screen`/`resume_screen` 复用 `TerminalGuard::enter`/`write_restore` 的 crossterm 序列。CLI `exit_tips` 复用同一 `check_tool_deps()` 探针（替换原私有 `tmux_available`/`deps_sentinel_exists`）。

## 依赖与接口
- 依赖：ratatui 0.29、crossterm（不再启用 `event-stream` feature——输入采集改专用线程 poll/read）、tokio、opencoder-session、opencoder-core、opencoder-store、opencoder-llm（estimate）。
- 被依赖：binary crate（`src/main.rs` → `opencoder_tui::run_tui`）。
- worker 通道：`UiCmd::{Prompt,SwitchAgent,SwitchAgentNoClear,SwitchAndStart,Compact,SetSkill,ReloadConfig,ResetCancel,Quit}` → `UiEvent::{Session(SessionEvent),TurnDone}`。worker 对每条 SessionEvent（含 token（loop 的 `cancel` 句柄同步重指），保证双击 Esc 中止后仍可提交。**`/task` 切换 cancel-before-Quit**：`switch_session`（`app_task.rs`）在发 `Quit` 前先 `cancel.cancel()`——worker 循环严格 recv→process→recv，mid-turn 排入的 Quit 阻塞。**跨重启上下文持久**：`SetSkill` 与 `SwitchAndStart` 经 `SessionPatch` 落库（`skill` / `handoff_seq` / `handoff_plan`），`KeyAction::SetSkill` 在 app 层 best-effort 持久化技能，故技能与 plan→act 移交边界跨重启保留。同理，`$skill` token 经 `store.admit_input` 成功后立即 `chat.push_marker` 推 `queued:`（warn 色）/`steer:`（accent 色）标记（均 BOLD）；消费/提升时（`QueueConsumed` 属 `app_loop.rs`、`SteerConsumed` 属 `chat.rs`）按事件携带的 `text` 推 `user:` 标记（warn/accent
