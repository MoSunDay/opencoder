# Review

## Overview

评审 = 回答五个必答问题 + 裁决上线结论。**输出 = 问一 ~ 问五 + 上线结论，共六个板块，顺序固定，板块之外零输出**。

**评审停在逻辑层**：不执行测试、不跑回归、不实跑命令验证——评审对象是变更逻辑本身，以及变更对受影响模块逻辑的潜在影响。

## 输出契约

- **严格五问**：只输出问一 ~ 问五与上线结论六个板块；不写开篇引言、过程叙述、评审方法论自述、结尾展望、致歉客套。
- **一行一条关键信息**：结论在前，证据（`file:line` / diff 引用）在后；删掉形容词、套话与重复铺垫。
- **不搬运原文**：不整段粘贴 diff、代码或文件内容，引用只给 `file:line` 加一行说明。
- **不跨板块复读**：问一复述过的目标不在后文重抄；问二列过的清单不在问四重列，问四只按问二的序号逐项核查。

## 问一：原始需求目标

- 逐字复述用户原始需求的目标与验收标准，不引申、不缩减、不重定义。
- 需求有变化时一行标注变化点。

## 问二：做了哪些事情及完成度

- 以 TODO 清单盘点实际改动：一行一项 = 做了什么 + 交付物位置（`file:line`）。
- 完成度一行给出：`completed/total` + 百分比（向下取整）。
- 未完成项只标状态，原因不在此展开（归问三卡点 / 问五 TODO）。

## 问三：卡点

- 一行一个卡点：卡在哪、阻塞了谁、需要什么（授权、审批、权限、凭证、外部依赖）。
- 无卡点显式写「无」。

## 问四：逐项逻辑核查

对问二的每一项改动静态核查（不实跑），每项固定两行：

- **逻辑本身**：推导是否成立、分支/边界/异常路径是否自洽、与既有约定是否一致；验证方式 = 当次 diff 对照 / 调用链追溯，证据 = `file:line`。
- **变更潜在影响**：列出被直接/间接触及的模块（调用方、被调用方、共享类型/接口、依赖的不变量），一行一模块判定是否仍自洽；无法静态判定的列入 `assumptions:` 或问五 TODO。

## 问五：下一步 TODO

- 输出编号 TODO List，按优先级排序，一行一项：动作 + 落地路径/所需条件。
- 无剩余事项写「无」。

## 上线结论

五问答完裁决：`go-live ready | not ready`。

| 情形 | 裁决 |
| --- | --- |
| 五问任一缺失或空泛（无逻辑依据支撑） | 直接 `not ready` |
| 五问齐备且逻辑核查与影响面评审无未闭环缺陷 | `ready`，并给出一句话理由 |

## 证据纪律

- **先查再定**：能从仓库、`rules/`、既有代码与注释、当次 diff 查到的事实先查再定，不把提问当侦察手段；查不到的推断列入 `assumptions:` 清单，标注「结论基于假设」。
- **不向用户提问**：需要用户裁决的事项写入问三卡点，由用户处置；绝不静默编造评审结论。
