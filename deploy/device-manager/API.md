# Device API v1

All routes require `Authorization: Bearer …`. The private host admin token is read from a configured file, never provided to a model. Capabilities are private transport values, not prompt or log material. Requests and responses use JSON.

- `POST /v1/step-sessions` (host admin): `{dag_id,step_id,session_id,role:"allocate",target_step,count}`. Returns the bound allocator scope and `capability`. An ended session cannot register again or authorize reservations; the session is rechecked within the allocation transaction.
- `POST /v1/step-sessions/:session_id/finish` (host admin): `{dag_id,step_id,instance_id,outcome}` where outcome is `done`, `error`, or `cancelled`. Identity must match a previously registered host session. Persisted host completion permits ownership recovery after instance metadata has moved to a new session. Missing proof fails closed; crash recovery must verify the old session stopped before the host supplies this endpoint.
- `POST /v1/reservations` (allocator capability): `{dag_id,target_step,count}`. Returns `{reservation_id,dag_id,target_step,count,assignments}`. Stable identity is `(dag_id,target_step)`; count changes are rejected. Assignments contain `instance_id` (strings `"0"`…`"N-1"`), `machine`, `generation`, `session_id`, `works`, `released`. Insufficient capacity returns 409 with no partial assignment. Every request requires an existing nonterminal DAG and an active allocator session; terminal reservations remain readable through status.
- `POST /v1/reservations/:id/claims` (host admin): `{instance_id,generation,session_id}`. Returns the assignment and private scoped `capability`. Same session is idempotent. A different session requires trusted confirmation that the previous session ended; generation/capability rotate. Missing old-session evidence rejects with no reassignment. `recovery_only=true` indicates a terminal DAG or unfinished work owned by the previous session/generation.
- `POST /v1/reservations/:id/work` (assignment capability): `{instance_id,generation,session_id,native_run_id}`. Persist this before any device action. Repeat for the same active work is idempotent. Before registering another case, all prior restoration receipts are reverified. A restored work cannot authorize more device actions. Repeating old-session work returns `recovery_only=true`; new work remains blocked until its recovery completes.
- `POST /v1/reservations/:id/completions` (assignment capability): same identity fields plus `receipts:{name:sha256}`. Names and fixed paths are in `src/receipts.mjs`. Multiple works append; they never replace earlier incomplete work. This records verified restoration, not pool release.
- `GET /v1/reservations/:id/status` (host, its allocator, or its current assignment capability): public reservation including session, generation and per-work recovery status, excluding all capabilities.
- `GET /v1/devices` (host admin): device allocation and quarantine states, no connection credentials.

Receipts live only under configured `evidence_root/<native_run_id>`. Paths are fixed; symlinks/escaping paths, mismatched hashes, owner, generation, machine or capture identity are rejected. `device-owner.json` fields: `{reservation_id,dag_id,instance_id,session_id,machine,generation,native_run_id}`. Original work ownership is retained when a new host session resumes it. Local `release.json` means the case restored its device; it MUST NOT free a parent reservation or mutate the legacy registry.

The reconciler polls existing OpenCoder execution and instance APIs. Only `done`, `error`, `cancelled` are terminal. Each device is released independently after its DAG ends and every registered work's restoration is reverified. Unclaimed assignments never started work and may release on DAG termination. Claimed assignments without work additionally require confirmed session termination. Unknown/404/network errors keep ownership. Capture `stop_failed` with verified collector cleanup may be safe for capacity release, while capture failure remains recorded.

The accepted nonterminal DAG states are `running`, `pending`, `queued`, `assigned`; any unrecognized state returns 503 and cannot authorize allocation, claims or work. Confirmed DAG outcomes are persisted in the existing state file's `dag_outcomes` map and survive restart. Terminal observations cannot be undone by delayed running responses. Allocation, claim and work gates are checked against the current ledger inside serialized transactions; assignment access also checks the device's reservation and generation. No timeout steals a device.

Server GET queries retry only HTTP 502/503/504 and known transient transport failures, at most eight attempts within the existing single 10-second default budget. Authentication, other HTTP errors, invalid content and identity mismatches fail immediately. Business POSTs are not retried. Upstream failures return HTTP 503 with safe `code` and, when available, `upstream_status`, `cause_code`, `attempts`; credentials and response bodies are excluded. Ownership remains held when authoritative state cannot be verified.

Initial state quarantines all 18 devices awaiting explicit legacy handoff. Migration must route or disable ALL legacy allocators before activating devices and preserve existing quarantine. No API allows a model to clear quarantine. Atomic state replacement, file and directory fsync, serialized mutations, and the service's OS flock protect committed batches and process restarts. Device activation requires a verified handoff; installing or starting the service does not activate devices.

For capture-only preparation failure, `run.task_start_attempted=false` and `cleanup.original_untouched=true` permit collector restoration instead of nonexistent supervisor receipts. Required proof names remain owner/run/cleanup/release/capture/manifest/firewall. In addition to case/machine/capture ownership and `manifest.cleanup_verified`, `manifest.integrity.https.cleanup` must contain `restored=true`, `collectorAlive=false`, and at least one true `active_marker_removed`, `active_marker_absent`, or `noop_verified`. Firewall removal must be verified. A started supervisor still requires the complete normal restoration receipts.

## UI candidate contract (not yet enabled)

The host may register an allocator session with `work_type:"ui"`, ordered `case_ids` and matching ordered `case_specs` (case ID, spec SHA-256, input version), then reserve with the same values. The service freezes those inputs into the reservation and each assignment. Native `/work` rejects UI reservations. A scoped UI assignment may call `POST /v1/reservations/:id/ui-work` with its host execution ID, assigned case ID, frozen spec SHA-256, input version and deterministic `ui_run_id`. `POST /v1/reservations/:id/ui-capture` runs the existing Windows capture start/stop driver from the manager process; mutating UI actions require a confirmed capture start. `POST /v1/reservations/:id/ui-actions` signs assigned Windows NodeAPI actions using its existing token file. `POST /v1/reservations/:id/ui-screenshots` obtains and hashes a current PNG into the owned run directory. Every operation ID is recorded before the remote call. A pending or uncertain outcome is never reissued automatically; capture stop remains available to a rebound recovery session.

`POST /v1/reservations/:id/ui-completions` accepts the same scoped assignment identity, `ui_run_id`, case ID and fixed receipt hashes. The manager independently reads `evidence_root/ui/<ui_run_id>/` and checks the frozen spec, every original assertion ID and its evidence reference, screenshot hashes against registered screenshot operations, capture identity against registered start/stop operations, all raw capture hashes against the collector manifest, collector cleanup integrity, and restoration receipt. `POST /v1/reservations/:id/ui-reconcile` can resolve an uncertain screenshot or capture operation only from owned, already persisted evidence; it never repeats the remote operation. Uncertain business actions remain unresolved and retain the reservation. It rechecks those files before release; missing or altered evidence retains the reservation. This file contract still needs a trusted case executor and live environment-restoration probe before production admission. `ui_device_v1` remains unadvertised until that end-to-end verification is complete.
