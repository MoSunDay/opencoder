# TODO 工作台

在 **Agent → TODO 管理** 中创建模板。新建与编辑都默认打开画布，可以添加 TODO、连接依赖、修改背景、执行说明、执行 Agent 和验收条件，并切换到表单或 JSON。父 Agent 固定为 `workflow`，负责根据目标调度与验收；每个 TODO 使用独立 Primary 会话执行。节点属性中的「预览派发上下文」显示目标、约束和任务内容；依赖结果、证据与恢复信息在实际派发时填入。

模板定义和环境绑定分别保存。运行启动时冻结定义；后续编辑模板不会改写已有运行。关闭有未保存修改的编辑器时会提示保留或放弃修改。

## Review

运行列表点击一行打开工作台：

- 左侧搜索、筛选和选择任务，画布显示真实状态、尝试次数与依赖关系。
- 右侧查看候选结果、验证说明、证据、工具门禁与父 Agent 验收理由。
- 「派发上下文」对应实际派发记录；「历史尝试」保留每次会话、返工和重跑过程，可打开指定尝试的上下文与会话。
- 父 Agent 会话集中记录调度与验收。子任务消息和工具事件从所属 Node 读取；大字段分段加载，历史记录可继续向前翻页。
- 页面显示最近同步时间。节点离线或数据读取失败会明确报错，恢复同步前禁用运行控制。

## 从指定 TODO 重跑

选择任意 TODO，点击「从选中节点重跑」，检查影响范围并填写原因。直接前置任务必须已经通过验收。系统先持久化请求，停止当前执行，等待子任务退出，再重新排队：

- 目标及所有下游任务重新执行，上游和无关分支的已通过结果保留。
- 现有文件和外部操作结果保留；这个操作不撤销已经发生的文件或外部变更。
- 原候选结果和会话历史保存在过程记录中；新的执行使用新一轮状态，有过会话的任务标记为 fork，创建新的独立会话，旧会话保留供 Review。
- 相同 request_id 的重复请求不会重复重跑。节点进程重启后继续处理已持久化请求；停止超时或恢复失败会显示失败原因。

普通「中断」保留恢复语义；「取消」终止当前执行。从节点重跑是独立的显式操作，也可用于已完成或失败的运行。

## 数据与接口

工作流仍使用现有 Store 状态与事件表，重跑受理写入 Node 执行账本；不增加数据库表或协议版本。调度事件携带提交后的节点状态、generation 和 world_epoch，页面结合快照水位去除重复或过期事件。

| 接口 | 用途 |
| --- | --- |
| `POST /api/todo/context-preview` | 预览任务上下文 |
| `GET /api/todo/workflows/:id/review` | overview、node、history、messages、session_events、session_event_payload |
| `POST /api/todo/workflows/:id/rerun` | request_id、todo_id、reason、expected_generation |

Review 会话接口验证会话属于当前工作流。现有管理员权限边界保持适用。旧运行缺少的派发上下文不会事后补造。
