# 大脑调度工作台

新计划使用固定核心流程：目标与输入 → 大脑调度 → 本轮能力执行 → 结果判断 → 完成；需要继续时回到下一轮调度。计划画布关联能力库，不再要求编辑 input、output、实例和路由节点。

## 创建与复用

在计划库创建计划，填写名称、目标、可选工程输入，并明确勾选允许调度的能力。支持 Agent、Team、DAG、TODO、Operator。计划使用 schema_version 3，默认最多 32 轮；保存到现有版本库，编辑生成下一版本，旧版本不会被覆盖。

执行指定版本时选择大脑所在节点，可覆盖本次工程输入；目标、能力范围和轮次上限由该版本确定。每次执行产生独立 run_id，并记录来源计划版本及最终输入。工作台也支持直接填写目标并选择能力启动一次运行。

服务端在保存、启动和每轮调度时核验能力范围；失效能力明确报错，越界能力不能派发。注册能力使用目标的真实执行定义，TODO 派发使用该轮取得的定义快照。没有必填工程输入的能力可仅凭目标执行，有必填输入时继续严格校验。

## 查看运行

核心流程下方按轮展示调度理由、依据执行、调用的能力 ID、执行类型和 execution_id。当前轮自动展开，已展开的历史轮次保留。轮次与理由从持久化记录恢复，刷新或重连不丢失。

待创建 ID 与已创建执行明确区分。点击已创建的 ID，在同页抽屉复用 ExecutionView；可直接切换轮次和执行类型，组件状态与订阅按 execution_id 隔离。消息、DAG 步骤、Team 对话、TODO 项和产物仍通过执行 ID 从所属节点读取。历史执行能力元数据读取派发回执，不用当前目录覆盖。

暂停、继续和取消作用于大脑统一调度。子执行托管面板不提供独立重跑。执行失败、阻塞、节点离线和读取错误直接展示；调度诊断默认折叠。

## 兼容与草稿

历史图计划和运行仍可只读查看。新计划草稿使用独立的 `oc:brain:scheduler-draft:v3:` 命名空间，旧版 `oc:brain:plan-draft:` 缓存保留。损坏草稿不会被静默覆盖，用户可先备份原文再重新开始。未新增数据库表或环境变量。
