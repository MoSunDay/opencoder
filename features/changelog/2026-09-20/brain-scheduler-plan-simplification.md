# 大脑计划简化与按轮执行明细

## 变更

- 新建、保存和复用 schema v3 调度计划。配置只含目标、工程输入、明确选择的能力与轮次上限；固定核心流转画布直接连接能力库。
- 保存、创建运行和每轮调度核验所选能力；已登记能力解析真实 Agent、Team、DAG、TODO、Operator 目标定义，不可用目标明确报错。
- 运行按轮展示持久化调度理由、判断依据、能力与类型、执行 ID；区分待创建 ID 和已经创建的执行，刷新后保留依据。
- 在大脑抽屉中按轮次和执行切换，复用各类型 ExecutionView，通过 ID 拉取执行详情。切换时清理旧订阅；子执行继续处于大脑管理上下文。
- 复用已有计划版本表，版本不可覆盖；运行冻结计划引用与能力身份。v2 历史计划在页面只读，旧浏览器缓存保留，v3 草稿独立保存并支持故障恢复。未新增数据库表或环境变量。

最终界面限制长目标摘要高度，保留展开入口；发布包的两轮五类型浏览器验收与动态 DAG 面板验收通过，全工作区 Clippy（包含所有 targets，警告视为错误）通过。

发布预检发现旧 Runtime 的重复 Create 会等待资源快照队列。候选探针现先读取持久化执行，核对完整请求、定义、类型、ID 和所属节点后恢复本次激活；缺失记录才创建，冲突立即报错，完成状态和 Runtime 就绪仍需校验。新增回执丢失、已完成探针恢复及冲突定义回归测试。

全量回归发现未确认接收的 v3 运行重试会误报 202。重试现在持有同一运行锁并复用冻结请求，通过统一执行回执判断是否已经接收；原节点离线且未确认时继续返回 503，已确认的接收回执则可在节点离线后安全重放。并发重试不会重新解析已冻结的能力范围。

冷资源准备使用独立的同 ID 创建锁，避免重试与执行生命周期锁形成等待环。队列领取容量到启动执行的过程由 Runtime 持有，提交连接断开不会遗留未启动的容量票据。新增同 ID 冷准备、断连后继续启动及真实 NFS 重试/重启验收。

线上连续性验收发现历史慢接收会在 Server 超时后继续占用 Host 控制通道。Host 对完整 Runtime 转发增加早于 Server 的超时边界：创建 45 秒，查询和控制 10 秒，覆盖锁、唤醒与响应读取；超时返回可重试错误，保留执行归属和原请求，不取消 Runtime 已接收的执行。回归覆盖超时释放共享锁、归属保持和原请求重试。
