# 保留每层原始调度理由与依据

已完成运行的层详情曾选择最后一条带 `decision_summary` 的事件，导致子执行终态覆盖调度理由，第一层显示“判断中”；最后一层则被整次运行完成判断覆盖。

层明细现在只读取本层 `layer_started` 的派发决策，并新增 `decision` 字段区分调度动作与执行状态。Web 展示“本层调度：派发本层”，当前状态继续由节点和层屏障展示。原始事件、执行 ID 和能力明细保持不变，无需迁移数据。已派发层缺失调度事件时明确报错。

回归覆盖完成、重试、失败、运行收口后的历史决策读取，以及 Web 状态与理由展示。最终发布验收回执在完成全部门禁后补充。

生产验收脚本将 step 描述限制在接口允许的 120 字以内，完整任务要求保留在计划目标与能力定义中，避免验收在创建计划时被拒绝。

全量回归发现旧接口夹具用空事件日志模拟已派发层，现补齐派发事件与执行索引。`layered_view_and_rounds_read_the_node_projection` 同时核验已派发层的理由和未来层的空决策；`dispatched_layer_without_history_is_an_explicit_error` 保证缺失历史仍明确返回错误，不伪造派发理由。

真实容器测试的画布与读取场景改用各自临时目录生成运行 ID，避免独立 Fleet 在默认并行测试或不同测试进程间复用全局 runc cgroup。保留原有断言和并行执行方式。

发布观察期间发现 Runtime 匿名内存约 150 GiB 后被 OOM 杀死，原观察窗口判失败。故障前的原生 `search /tmp` 在 130 秒后超时；代码核实其阻塞搜索不随调用取消、默认不检测二进制、行缓冲无上限。未保存被杀进程的堆快照，不能断言具体触发文件。

修复为二进制检测、1 MiB 行缓冲上限、64 KiB 搜索结果缓冲上限，并在遍历、分块读取和匹配处响应调用取消。超长文本行和读取错误明确报错。隔离输入为 256 MiB 连续 NUL：旧配置读完整个输入、峰值 RSS 425948 KiB；新配置读取 3 字节即停止、峰值 RSS 14788 KiB。新增回归覆盖二进制邻接文本、长行、UTF-8 输出边界、取消后阻塞读取退出与错误展示；原搜索契约仍需通过。生产稳定性必须在修复版重新发布后重新累计完整观察窗口。

信号回滚及再发布验收中，622 次请求均接收成功，但最长接收耗时 2.218 秒，超过 1 秒门槛，该轮验收判失败。检查发现主节点约 1.2 万条执行索引的同步逐条查询及写入，并持有共享写锁；隔离基准中首次写入耗时 1.401 秒，重复同步约 155 毫秒。此为已确认的锁占用开销，尚不能仅据此断言此次生产延迟的唯一原因。

索引同步改为事务内批量校验不可变字段、批量插入及仅更新变化的状态，序列化放在共享写锁之外。保留报告代次隔离、待调度恢复与整批原子回滚，不新增表、字段或环境变量。针对性回归覆盖万级无变化库存零重写、64 位创建时间、归属冲突后状态及报告序号回滚，以及既有报告与发布交接契约；生产切换延迟仍须按原 1 秒门槛重新验收。

修复后的同规模隔离基准：首次同步 0.158 秒，无变化同步 0.060–0.062 秒；2 项新增回归、4 项报告契约、5 项发布交接契约通过。

第二次信号回滚及再发布的 568 次请求全部完成，仍有一次接收耗时 1.068 秒，超过原 1 秒门槛，该轮继续判失败。慢请求在创建执行索引前等待约 745 毫秒，索引创建到开始执行为 23 毫秒。发现待派发恢复查询在共享 Fleet 锁内扫描并解析历史任务的完整快照，首次只读实测约 532 毫秒；固定只读数据库快照上的热查询约 118 毫秒。

待派发查询改为先选取 prepared 回执，再按 ID 读取对应任务；Project 通过已有执行索引筛选后按当前运行 ID 关联回执。同一只读快照实测约 21 毫秒，返回任务及冻结输入与原查询完全一致。不增加索引、表或字段，保留回执范围、128 条分页上限、Project 旧输入兼容及只重试明确未接受派发的规则。新增 4 项回归覆盖混合类型、分页、索引与请求不一致及损坏类型记录，连同 11 项既有报告、交接及 Project 派发契约通过；Clippy 和格式检查通过。发布连续性仍按原门槛重新验收。

待派发查询依赖的索引 ID/类型一致性在写入前显式校验；缺失或损坏的待派发请求类型仍进入反序列化并明确报错，不静默跳过。

就绪检查改用按类型、状态聚合的计数查询，避免分页加载全部历史记录；固定只读快照中的 23792 条记录、3499 个活跃任务计数不变，查询约 676 毫秒降至 22 毫秒。3 项计数、4 项准入和 4 项排空契约通过。Worker 增加超过 250 毫秒才输出的准入阶段耗时日志，用于区分资源预检、持久化、锁等待及容量调度；日志不包含任务输入和配置，相关 10 项回归通过。

容量轮询复用已有 `one_live_slot` 索引，只遍历未完成票据；保留历史、全机 FIFO 和事务内容量复核，不新增索引或配置。17854 条完成历史、2 条运行票据的只读快照中，结果一致，热查询约 1.2 毫秒降至 2 微秒。新增 2 万条完成历史下跨 Runtime 排队测试，连同相关容量、交接及断线重试共 9 项通过。

Host 库存归属校验改为整批查询；全部已知时只读，有新 ID 时在写事务内再次校验并原子补录，冲突不留下部分归属。18921 条记录的只读对比约 248 毫秒降至 18 毫秒。相关 13 项测试通过；与容量修复合并后，另有 5 项组合测试通过，包括三个 Runtime 的在途模型任务与全机 FIFO。以上改动的相关 Clippy、格式检查通过。

`565c0eae` 已部署，六类执行面板、原始调度历史及原生搜索验收通过。当前版本新建失败样例 `brain-history-failure-1790065990` 验证了两个不同执行 ID 均失败、根运行按两次尝试上限失败、派发理由保留。正式切换验收的 689 个请求全部完成，但最大受理耗时 1.086 秒、受理间隔 1.186 秒、调度间隔 1.460 秒，仍未通过原 1 秒门槛，不能视为完整交付。

后续验收补齐应用日志 `ERROR` 级别识别，避免只按 journald 优先级漏计错误；基线探针固定到目标 Runtime 所属节点并检查实际执行文件，避免被调度到其他节点；切换后基线就绪检查在 180 秒内连续三次确认至少 4 个节点就绪。正式流量的三项 1 秒门槛不变，仍需完成回滚重发、SSE 恢复和完整 900 秒观察后补充最终交付回执。

实际回滚发现端口分配只避开发布记录，误用已由 MySQL 占用的 3306 端口，Host 健康检查收到 MySQL 握手而失败。发布控制器现在同时探测整组本地端口的可绑定性，初次部署与旧版本重新激活共用该规则；不连接或修改占用端口的服务。探测不等于持续保留端口，后续竞争占用仍由启动检查明确报错。

在线备份在只读源连接上先开启并固定 WAL 读取快照，再分步复制，避免并发写入使复制反复重启；源、目标连接均显式关闭，保留完整性检查和持久化要求。新增真实端口冲突、端口边界、部署与重新激活、并发写入下备份快照一致性测试，连同直接相关回归共 59 项 Python 测试通过。未改动 Rust 业务代码与 SPA，其既有验收通过源码及构建哈希核验复用。
