# OpenCoder 能力地图

OpenCoder 当前提供以下用户/调用方可感知的能力。每项链接到对应的业务文档或逻辑模块。

## 能力组

- **多节点分布式执行（server ↔ node）**：`opencode node --remote <server>` 把任意机器注册为执行节点（bearer token，同名顶替）；web「Nodes」面板看 online/idle/busy/lost、下发 prompt——任务用**节点本地配置与 LLM 凭证**跑完整 agent session，事件实时回传浏览器直播；注册表/任务/事件全量落 server libsql，断流按 `after=` 续传零丢失。详见 [changelog](changelog/2026-08-26/multi-node-distributed-execution.md)。
- **CLI/MCP 注册与 Agent 范围注入**：TUI `/cli` 管理自由文本 CLI usage contract（多行编辑器），`/mcp` 管理 MCP server；两类条目均可启停，`inject_to` 以 parent/explore/build 多选（勾选对话框）决定注入对象，粒度到单个子 Agent。CLI 内容条件性进入 system prompt，MCP 范围同时约束提示和工具可见性。详见 [changelog](changelog/2026-08-15/inject-to-multiselect-and-content-editor.md)。
- **Skill context 尾部注入**：skill 内容离开 system prompt——每次 LLM 调用按需合成瞬时 user 尾消息（`[skills]` 目录 + `[active skill]` 源路径，模型按需读 SKILL.md；不落库、压缩后重生成），TUI `/skill` 弹窗管理默认注入开关。详见 [changelog](changelog/2026-08-15/skill-context-tail-injection.md)。
- **配置按域拆分为独立文件（mcp/cli/skills/ap.json）**：`mcp_servers`/`cli`/`skills`/`autopilot` 四域键硬切出 `config.json`（遗留键加载时忽略，**breaking**）——各自经专属域文件 `<workdir>/.opencoder/{mcp,cli,skills,ap}.json`（项目）或 `~/.opencoder/{mcp,cli,skills,ap}.json`（全局）加载/保存，项目存在则整体遮蔽全局。详见 [changelog](changelog/2026-08-16/split-domain-config-files.md) / [autopilot 域 changelog](changelog/2026-08-20/envs-autopilot-domain.md)。
- **`/envs` 环境配置管理**：每个环境是 `~/.opencoder/envs/<name>/` 完整配置快照（config.json + mcp/cli/skills/ap.json，0o600），激活后插入解析链 **project > env > ~/.opencoder > XDG**；激活期间交互式编辑（`/model` 等）落进环境层（save_target 截断）。TUI `/envs` 弹窗（列表/新建/重捕获/删除）、web `/api/envs` REST、CLI `config show` stderr 提示行。详见 [changelog](changelog/2026-08-16/envs-config-management.md)。
- **持久化 TODO 工作流**：`opencoder todos validate/run/resume/show/events/list/interrupt` 执行预编译通用 TODO 合同；父 Workflow Session 管理全局依赖、状态、并发、验收和回退，每个 TODO 使用独立 Primary Session 聚焦完成。Store 是权威状态，`--debug` 才生成可索引文件投影。详见 [TODO 工作流](todos/index.md)。
- **plan 模式结构化提问**：模型经 `question` 工具向用户提问（仅 plan agent 注入 schema），TUI 弹出对话框（预设选项 + 自定义输入），作答作为 tool result 同轮回填驱动继续规划；headless/web 无监听时固定文案兜底不挂起。详见 [changelog](changelog/2026-08-14/plan-question-tool.md)；2026-08-21 起提示词全面 ask-by-default（有疑必问、先查再问）：[changelog](changelog/2026-08-21/plan-question-always-ask.md)。
- **plan 计划阶段有界快照**：plan agent 回复在记录时刻即捕获 `plan_snapshot` + `plan_input_count` 落库（schema v10，压缩/重启前已持久）；plan→act handoff **只读快照**（不扫 transcript），本阶段无计划产出则不交接、不清上下文；溯源门武装移到**消费时刻**（TurnDone 按持久计数重武装），admit/queue/steer 落库不武装——滞留提交不再引发假计划交接或偶发清空全部上下文。详见 [changelog](changelog/2026-08-18/plan-phase-persistence.md) / [阶段有界快照 changelog](changelog/2026-08-19/plan-handoff-phase-bounded-snapshot.md)。
- **会话恢复**：CLI `--session <id>` / `--continue` / `--fork`，跨进程从 libsql 重建历史；title 由 small_model 异步生成。详见 [agents/session](../agents/session/index.md)。
- **Session 二进制导出/导入**：`opencoder session export <id> -o <file>` 导出 session（含 subagent 树）为 `.opencoder` 二进制文件（`OPENCODR` magic）；`opencoder session import <file>` 幂等导入到新环境，`--session <id>` 可继续执行。不导出 Config（API key 安全）。详见 [agents/store](../agents/store/index.md) / [bundle changelog](changelog/2026-07-06/compact-clear-display-session-bundle.md)。
- **模型与压缩配置化**：`providers` 命名表（`base_url/api_key/model/headers`）+ `model = "{provider}/{id}"` 选择、`small_model`、`context_limit`、`max_tokens`、`reasoning_effort`、`compaction.{auto,context_threshold,reserved,tail_turns,buffer}`、自定义 HTTP `headers`（`{ENV_VAR}` 解析）全可经 opencoder.json / 环境变量 / CLI flag 配置；压缩首轮即可由 token 估算触发。TUI `/config`（生成参数）与 `/model`（Provider CRUD + headers）分治。详见 [agents/session](../agents/session/index.md)、[agents/core](../agents/core/index.md)、[压缩提示词+token 追踪修复](changelog/2026-07-11/compaction-prompt-and-token-tracking.md)。
- **推理显示（max/xhigh）**：`💭 Thinking` 标签在高推理档位可靠且在首个推理帧到达时立即出现。上游 `extract_reasoning` 接受 `reasoning_content`/`reasoning`/`thinking` 等别名与结构化 thinking 块，末帧回退受双发射守卫保护；TUI 仅合并已显示折叠块的后续隐藏增量，不再吞掉新块首帧。详见 [agents/llm](../agents/llm/index.md) / [agents/tui](../agents/tui/index.md) / [max-xhigh reasoning changelog](changelog/2026-08-08/max-xhigh-reasoning-thinking-label.md) / [Thinking 首帧可见 changelog](changelog/2026-08-08/thinking-first-frame-visible.md)。
- **助手输出精简（保义归一化）**：每轮助手文本在流式送达 UI 后、持久化与回送上下文前，经确定性纯函数 `streamline` 归一——去散文尾部空白、连续空行收敛为单行、裁首尾空行；**fenced 代码块逐字节透传**，确保保义。单点同时削减存储与后续 input token，零额外 LLM 调用。由 `output_streamline` 配置子段驱动（`collapse_inline_ws` opt-in）。详见 [output-streamline changelog](changelog/2026-07-25/output-streamline.md)。
- **steer / followup（两段式 delivery）**：运行中的会话可在 turn 边界吸收 steer（重置步数配额），idle 时消费恰好一条 queue。HTTP `POST /prompt` 带 `delivery`。详见 [agents/session](../agents/session/index.md)。
- **Web 会话操作**：HTTP CRUD + SSE 事件流（replay+live）+ 运行时 agent/model 切换 + interrupt；会话列表支持 `?workdir=` 过滤（`workdir_hash` 戳）、事件流支持 `Last-Event-ID` 回退。详见 [agents/web](../agents/web/index.md)。
- **Web question 交互闭环**：plan 模式 `question` 工具在 web drain 下等待作答——`GET /api/sessions/:id/questions` 轮询（attach-on-poll）+ `POST .../questions/:call_id/answer|skip`，前端 1.5s 轮询卡片（选项按钮/自由文本/跳过、乐观 resolve）；最后一个 SSE 订阅者断开时 abandon → 工具得 SKIPPED。详见 [changelog](changelog/2026-08-21/web-tui-parity-server-client.md)。
- **Web queue/steer 输入管理**：`GET /inputs?delivery=queue|steer`、`DELETE /inputs/:seq`、`POST /inputs/reorder`；前端 pending 输入抽屉（删除/重排/badge 计数）。详见同 changelog。
- **Web annotation/autopilot/plan 相位端点**：`POST /annotation`（requirement 设置/清空）、`POST /autopilot`（会话级 off|ap|review override，null 清除）、切回 plan 时 `ResetPlanPhase` 并持久化 `plan_input_count=0`。详见同 changelog。
- **Web 模型/技能发现端点**：`GET /api/models`（脱敏——永不返回 api_key/headers，去重下拉列表）、`GET /api/skills`（仅 name/description/enabled）；前端模型下拉从端点拉取（自定义回退）。详见同 changelog。
- **Web 会话标题 LLM 生成**：首次 drain run 成功后 best-effort small_model 生成（30s 超时，已有 title 跳过，失败非致命）。详见同 changelog。
- **Web 前端模块化 + SSE 重连**：assets 拆为 8 模块（api/sse/sessions/chat/composer/questions/queue_panel/settings，各 ≤400 行，编译期内联单二进制）；SSE 断线重连（`/seq` + `?after=` 续订，5 次退避 1..16s，badge+banner）。详见同 changelog。
- **`opencode client` 操作旗标 + 会话管理 + 断线重连**：`--delivery/--skill/--fork/--compact/--handoff/--autopilot/--annotation/--steer-task/--workdir` 编排（fork→autopilot→annotation→终态操作→prompt→stream）与 `client session list|show|delete|fork`、`client questions list|answer|skip` 子命令；SSE 断流自动重连（3 次退避 500ms/1s/2s，`/seq` 快照续订，放弃时 transcript 快照兜底）；`--continue` 按 workdir 过滤。详见 [agents/client](../agents/client/index.md) / [changelog](changelog/2026-08-21/web-tui-parity-server-client.md)。
- **高性能本地存储**：libsql 嵌入 + WAL，并发读写；`Store` trait 为切换其它 Rust SQLite 实现留口子。详见 [agents/store](../agents/store/index.md)。

- **autopilot 三态模式**：`config.autopilot.mode`（`off` / `ap` / `review`，默认 `off`；旧布尔 `enabled` 在 config 合并层迁移 true→ap / false→off，mode 键优先）。初始任务完成后 runner 按 mode 分发：`ap` → `autopilot::drive` 反复执行 PLAN→ACT→VERIFY 直到 VERIFY（small_model 隔离 shadow 一次性调用，判定交换不写入主 transcript；判定**严格单 token** 解析——限定性回答如 "Yes, but…" 视为无判定重试）回答「完成」、`verify_retries` 次内无可解析判定（Aborted reason 区分成因：verdict unparseable / judge unreachable，后者携带最后一次传输错误）、或已完成迭代达 `max_iterations`；`review` → `autopilot::review_pass` **仅当 primary agent 为 act**（runner 分发层 `AgentKind::Act` 门控——review 评的是已执行的工作，plan 模式等非 act primary 落入与 `off` 相同的空分发，不发起）**一次性** review turn（切 plan agent + 激活 review skill + 合成 review prompt 跑单次 run_loop，不进 ACT/VERIFY，结束清 skill 并发 `Done`）；`off` → 无任何自动行为。每阶段发 `SessionEvent::AutoPilot` 进度事件（含 `Review` phase；TUI 状态栏 / CLI / web SSE 可观测）；doom-loop / tool-failure guard 在 `run_loop` 内按**单次 run（即单个 phase）作用域**累计——phase/迭代边界重置、跨迭代不累计，整轮循环由 `max_iterations` 兜底；cancel 在 drive 循环边界检查（`review_pass` 入口亦有 pre-flight 取消检查）；todos workflow 路径强制 off。TUI `/ap` 打开三选一模式菜单（选择即保存），chip：ap→`AP`、review→`RV`；`/model` 表单保留 `max_iterations` 编辑。详见 [agents/session](../agents/session/index.md) / [autopilot changelog](changelog/2026-07-28/autopilot-loop.md)。
- **Skill 选择（TUI `$`）**：空 composer 输入 `$` 弹出技能选择器，扫描 `~/.opencoder/skills`（识别 `<name>.md` 与 `<name>/SKILL.md`，可选 `---` frontmatter 的 `name`/`description`）。↑/↓ 移动、键入即过滤、Enter 激活、Esc 取消。激活后经 context 尾部 `[active skill]` 提醒投递 skill 源路径（模型按需读 SKILL.md，正文不再进系统提示），one-shot 生效（skill 仅存活于触发它的那次 run：run 结束 Done/Error/cancel 即从内存与 `sessions.skill` 清除；run 中崩溃则 resume 保留至续跑完成），状态栏显示 `skill:<name>`；「✕ clear」行可手动提前清除。二进制随附内置 skill（首启 seed 到 `~/.opencoder/skills`）：`task-plan`（Codex 标准的上线闭环规划：证据成熟度、合约/保鲜、生产等价验证和遗漏复查，并随包 seed `references/` 细则）、`do-and-done`（实现循环）、`repo-local-memory`、`repo-local-dreaming`（周期性记忆整理/做梦）、`say-and-replay`（只读对齐快照——五问复述必答：目标/做了什么/遇到的卡点/验证方式+证据/下一步 TODO）、`review`（参考 Codex `say-and-replay` 的证据模型，评审完成百分比、当次证据、全局影响、交付卡点与 go-live 结论）、`summary`（任务回顾/recap——任一节点产出结构化回顾）、`submit`（提交）；`task-plan → do-and-done → review → submit` 为主链，`summary` 为正交的任务回顾工具（任一节点可用，不强制插入主链）。另有两个依赖门控 skill（`ssh-pty`、`chrome-headless`）：经 `install-skills-dep.sh` 哨兵文件 opt-in 开启、首启不 seed。详见 [agents/core](../agents/core/index.md)、[agents/session](../agents/session/index.md) / [skill-picker changelog](changelog/2026-07-05/skill-picker.md)。
- **模型配置与首启引导**：交互式启动确保 `~/.opencoder/config.json` 存在；有效 project/env 配置可直接使用，缺少凭证或端点不可构建时则在 TUI 内引导填写第一个 OpenAI-compatible provider、model、base_url、API key 与 headers。本地校验成功后固定保存到全局配置，按 global → project → CLI/env 完整重载并直接进入任务 composer，不产生探测模型调用。日常 `/model` 继续提供 Provider CRUD、全局默认或 session-only 切换；`/config` 独立管理推理、上下文和渲染参数。详见 [agents/core](../agents/core/index.md)、[agents/tui](../agents/tui/index.md)。
