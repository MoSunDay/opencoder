# OpenCoder 能力地图

OpenCoder 当前提供以下用户/调用方可感知的能力。每项链接到对应的业务文档或逻辑模块。

## 能力组

- **CLI/MCP 注册与 Agent 范围注入**：TUI `/cli` 管理自由文本 CLI usage contract（多行编辑器），`/mcp` 管理 MCP server；两类条目均可启停，`inject_to` 以 parent/explore/build 多选（勾选对话框）决定注入对象，粒度到单个子 Agent。CLI 内容条件性进入 system prompt，MCP 范围同时约束提示和工具可见性。详见 [changelog](changelog/2026-08-15/inject-to-multiselect-and-content-editor.md)。
- **Skill context 尾部注入**：skill 内容离开 system prompt——每次 LLM 调用按需合成瞬时 user 尾消息（`[skills]` 目录 + `[active skill]` 源路径，模型按需读 SKILL.md；不落库、压缩后重生成），TUI `/skill` 弹窗管理默认注入开关。详见 [changelog](changelog/2026-08-15/skill-context-tail-injection.md)。
- **配置按域拆分为独立文件（mcp/cli/skills.json）**：`mcp_servers`/`cli`/`skills` 三域键硬切出 `config.json`（遗留键加载时忽略，**breaking**）——各自经专属域文件 `<workdir>/.opencoder/{mcp,cli,skills}.json`（项目）或 `~/.opencoder/{mcp,cli,skills}.json`（全局）加载/保存，项目存在则整体遮蔽全局。详见 [changelog](changelog/2026-08-16/split-domain-config-files.md)。
- **`/envs` 环境配置管理**：每个环境是 `~/.opencoder/envs/<name>/` 完整配置快照（config.json + mcp/cli/skills.json，0o600），激活后插入解析链 **project > env > ~/.opencoder > XDG**；激活期间交互式编辑（`/model` 等）落进环境层（save_target 截断）。TUI `/envs` 弹窗（列表/新建/重捕获/删除）、web `/api/envs` REST、CLI `config show` stderr 提示行。详见 [changelog](changelog/2026-08-16/envs-config-management.md)。
- **持久化 TODO 工作流**：`opencoder todos validate/run/resume/show/events/list/interrupt` 执行预编译通用 TODO 合同；父 Workflow Session 管理全局依赖、状态、并发、验收和回退，每个 TODO 使用独立 Primary Session 聚焦完成。Store 是权威状态，`--debug` 才生成可索引文件投影。详见 [TODO 工作流](todos/index.md)。
- **plan 模式结构化提问**：模型经 `question` 工具向用户提问（仅 plan agent 注入 schema），TUI 弹出对话框（预设选项 + 自定义输入），作答作为 tool result 同轮回填驱动继续规划；headless/web 无监听时固定文案兜底不挂起。详见 [changelog](changelog/2026-08-14/plan-question-tool.md)。
- **会话恢复**：CLI `--session <id>` / `--continue` / `--fork`，跨进程从 libsql 重建历史；title 由 small_model 异步生成。详见 [agents/session](../agents/session/index.md)。
- **Session 二进制导出/导入**：`opencoder session export <id> -o <file>` 导出 session（含 subagent 树）为 `.opencoder` 二进制文件（`OPENCODR` magic）；`opencoder session import <file>` 幂等导入到新环境，`--session <id>` 可继续执行。不导出 Config（API key 安全）。详见 [agents/store](../agents/store/index.md) / [bundle changelog](changelog/2026-07-06/compact-clear-display-session-bundle.md)。
- **模型与压缩配置化**：`providers` 命名表（`base_url/api_key/model/headers`）+ `model = "{provider}/{id}"` 选择、`small_model`、`context_limit`、`max_tokens`、`reasoning_effort`、`compaction.{auto,context_threshold,reserved,tail_turns,buffer}`、自定义 HTTP `headers`（`{ENV_VAR}` 解析）全可经 opencoder.json / 环境变量 / CLI flag 配置；压缩首轮即可由 token 估算触发。TUI `/config`（生成参数）与 `/model`（Provider CRUD + headers）分治。详见 [agents/session](../agents/session/index.md)、[agents/core](../agents/core/index.md)、[压缩提示词+token 追踪修复](changelog/2026-07-11/compaction-prompt-and-token-tracking.md)。
- **推理显示（max/xhigh）**：`💭 Thinking` 标签在高推理档位可靠且在首个推理帧到达时立即出现。上游 `extract_reasoning` 接受 `reasoning_content`/`reasoning`/`thinking` 等别名与结构化 thinking 块，末帧回退受双发射守卫保护；TUI 仅合并已显示折叠块的后续隐藏增量，不再吞掉新块首帧。详见 [agents/llm](../agents/llm/index.md) / [agents/tui](../agents/tui/index.md) / [max-xhigh reasoning changelog](changelog/2026-08-08/max-xhigh-reasoning-thinking-label.md) / [Thinking 首帧可见 changelog](changelog/2026-08-08/thinking-first-frame-visible.md)。
- **助手输出精简（保义归一化）**：每轮助手文本在流式送达 UI 后、持久化与回送上下文前，经确定性纯函数 `streamline` 归一——去散文尾部空白、连续空行收敛为单行、裁首尾空行；**fenced 代码块逐字节透传**，确保保义。单点同时削减存储与后续 input token，零额外 LLM 调用。由 `output_streamline` 配置子段驱动（`collapse_inline_ws` opt-in）。详见 [output-streamline changelog](changelog/2026-07-25/output-streamline.md)。
- **steer / followup（两段式 delivery）**：运行中的会话可在 turn 边界吸收 steer（重置步数配额），idle 时消费恰好一条 queue。HTTP `POST /prompt` 带 `delivery`。详见 [agents/session](../agents/session/index.md)。
- **Web 会话操作**：HTTP CRUD + SSE 事件流（replay+live）+ 运行时 agent/model 切换 + interrupt。详见 [agents/web](../agents/web/index.md)。
- **高性能本地存储**：libsql 嵌入 + WAL，并发读写；`Store` trait 为切换其它 Rust SQLite 实现留口子。详见 [agents/store](../agents/store/index.md)。
- **glm5.2 端到端（深度契约）**：`scripts/e2e_glm.py`（`scripts/e2e-glm.sh` 为薄 wrapper）用真 glm5.2 验证**业务契约**而非表面标记。深度观测面为 `opencoder session show <id> --json`（meta + 全 ContentBlock + subagent_tasks，解耦存储内部）。覆盖 14 项：E7/E9 reasoning_effort/interleaved_thinking 显示、E1/E6 write+bash 写游戏并编译（含「工具真被调用」日志断言）、E2 `--continue` 恢复**且加载了首轮上下文**（历史含 turn-1 内容）、E5 `--fork` **复制消息且原 session 角色序列/计数不变**、E3/E3b 压缩自动触发 **+ 摘要引用实际工作 + 压缩后上下文可用**、E4 subagent 派遣 **+ DB 跟踪到终态 + 父答案引用调查**、E8 bundle 导出/导入 **roundtrip 完整性（消息计数相等 + 文本内容相同 + 角色序列相同）**、E10 plan agent **只读（无法创建文件）**、E12 session list+delete 生命周期、E13 交错思考 reasoning_content 持久化、E14 config show 合法 JSON、E11 web **两段式 delivery（steer 即时 + queue idle 消费，两个 prompt 都投递）**、E18 autopilot **自驱动循环 CLI 全链路**（config 合并 enabled/max_iterations + display 阶段标记 Plan/Act/Verify(iteration 0) + 注入 phase prompt 落库）、E18b web SSE **autopilot 阶段事件流**（`event: autopilot` plan→act→verify + 终态 done）。模型依赖项用 soft-skip；确定性存储契约（fork/bundle/resume/plan 只读）用 hard assert。注：交错思考的 reasoning_content 真实回传契约仅在强制该行为的模型（DeepSeek-V4）上可完整验证；持久化逻辑由集成测试 `session/tests/interleaved_thinking.rs` 覆盖。

- **autopilot 三态模式**：`config.autopilot.mode`（`off` / `ap` / `review`，默认 `off`；旧布尔 `enabled` 在 config 合并层迁移 true→ap / false→off，mode 键优先）。初始任务完成后 runner 按 mode 分发：`ap` → `autopilot::drive` 反复执行 PLAN→ACT→VERIFY 直到 VERIFY（small_model 隔离 shadow 一次性调用，判定交换不写入主 transcript）回答「完成」、连续 malformed 达 `verify_retries`、或已完成迭代达 `max_iterations`（行为与旧 `enabled=true` 完全一致）；`review` → `autopilot::review_pass` **一次性** review turn（切 plan agent + 激活 review skill + 合成 review prompt 跑单次 run_loop，不进 ACT/VERIFY，结束清 skill 并发 `Done`）；`off` → 无任何自动行为。每阶段发 `SessionEvent::AutoPilot` 进度事件（含 `Review` phase；TUI 状态栏 / CLI / web SSE 可观测）；既有 doom-loop / tool-failure guard / cancel 约束不被绕过；todos workflow 路径强制 off。TUI `/ap` 打开三选一模式菜单（选择即保存），chip：ap→`AP`、review→`RV`；`/model` 表单保留 `max_iterations` 编辑。详见 [agents/session](../agents/session/index.md) / [autopilot changelog](changelog/2026-07-28/autopilot-loop.md)。
- **Skill 选择（TUI `$`）**：空 composer 输入 `$` 弹出技能选择器，扫描 `~/.opencoder/skills`（识别 `<name>.md` 与 `<name>/SKILL.md`，可选 `---` frontmatter 的 `name`/`description`）。↑/↓ 移动、键入即过滤、Enter 激活、Esc 取消。激活后经 context 尾部 `[active skill]` 提醒投递 skill 源路径（模型按需读 SKILL.md，正文不再进系统提示），整会话生效，状态栏显示 `skill:<name>`；再次选择替换，已激活时首行「✕ clear」清除。二进制随附内置 skill（首启 seed 到 `~/.opencoder/skills`）：`task-plan`（全局规划/产出 STATUS 块）、`do-and-done`（实现循环）、`repo-local-memory`、`repo-local-dreaming`（周期性记忆整理/做梦）、`say-and-replay`（只读对齐快照）、`review`（上线前评审）、`summary`（任务回顾/recap——任一节点产出结构化回顾）、`submit`（提交）；`task-plan → do-and-done → review → submit` 为主链，`summary` 为正交的任务回顾工具（任一节点可用，不强制插入主链）。另有两个依赖门控 skill（`ssh-pty`、`chrome-headless`）：经 `install-skills-dep.sh` 哨兵文件 opt-in 开启、首启不 seed。详见 [agents/core](../agents/core/index.md)、[agents/session](../agents/session/index.md) / [skill-picker changelog](changelog/2026-07-05/skill-picker.md)。
- **模型配置与首启引导**：交互式启动确保 `~/.opencoder/config.json` 存在；有效 project/env 配置可直接使用，缺少凭证或端点不可构建时则在 TUI 内引导填写第一个 OpenAI-compatible provider、model、base_url、API key 与 headers。本地校验成功后固定保存到全局配置，按 global → project → CLI/env 完整重载并直接进入任务 composer，不产生探测模型调用。日常 `/model` 继续提供 Provider CRUD、全局默认或 session-only 切换；`/config` 独立管理推理、上下文和渲染参数。详见 [agents/core](../agents/core/index.md)、[agents/tui](../agents/tui/index.md)。
- **可重绑定键盘快捷键（TUI Ctrl+H）**：20 个快捷键（quit/cancel/help/newline/cursor/delete_word/clear_input/switch_mode/paste_image/undo/redo/word_move/switch_mode_clear/switch_mode_keep/collapse_blocks/force_redraw/copy_mode）可经 `opencoder.json` 的 `"keymap"` 段配置，或按 **Ctrl+H** 弹出模态交互式捕获新绑定——选中行 Enter → 按键 → Esc 保存、Ctrl+R 恢复默认，即时热重载。`KeyCombo::matches` 兼容多种终端键盘协议（BackTab 归一化、raw 控制字符、Kitty REPORT_EVENT_TYPES）。详见 [agents/tui](../agents/tui/index.md) / [keymap changelog](changelog/2026-08-07/tui-keymap-short-key-rebindable.md) / [Ctrl+H 迁移 changelog](changelog/2026-08-08/tui-ctrl-h-keymap-menu-migration.md)。
- **信息区文本选择/复制（Ctrl+G copy 模式）**：跨终端可靠的信息回显区文本选择——`Ctrl+G`（`keymap.copy_mode`，可配置）toggle 进入 copy/selection 模式，关闭 TUI 鼠标捕获 + tmux `mouse` 拦截，将原始拖拽交还终端模拟器执行原生选择（任意终端，不限 Kitty/WezTerm）；活跃时吞掉所有按键（Ctrl+G/Esc 退出）、短路所有点击交互；退出恢复 TUI 鼠标捕获但保持 tmux mouse off。Kitty Shift 按住增强路径（`consume_modifier_or_release`）保留共存。copy 模式激活时 body 边框高亮 + composer `COPY MODE` chip。详见 [agents/tui](../agents/tui/index.md) / [copy-mode changelog](changelog/2026-08-09/tui-copy-selection-mode.md)。
- **测试规则与覆盖**：[rules/](../rules/) 目录建立强制测试规则（每功能必有测试 + 迭代回归 gate + 测试分层）；workspace 测试覆盖 LLM 流式原语 / CLI（含 `session show --json` 深度观测面）/ 工具 / subagent / bash_guard / TUI / Web（HTTP 契约 + drain 生命周期）/ prompt / store CRUD / bundle 导出导入 / fork / interleaved thinking（具体数量见 `cargo test` 当前输出）。详见 [迭代四 changelog](changelog/2026-07-05/iteration4-test-coverage-rules.md)。
