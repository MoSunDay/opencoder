# OpenCoder 能力地图

OpenCoder 当前提供以下用户/调用方可感知的能力。每项链接到对应的业务文档或逻辑模块。

## 能力组

- **多节点分布式执行（server ↔ node）**：`opencode daemon --client --remote <server>` 把任意机器注册为执行节点（uplink 全量 HMAC 签名，同名顶替）；web「Nodes」面板看 online/idle/busy/lost、下发 prompt——任务用**节点本地配置与 LLM 凭证**跑完整 agent session，事件实时回传浏览器直播；注册表/任务/事件全量落 server libsql，断流按 `after=` 续传零丢失。详见 [changelog](changelog/2026-08-26/multi-node-distributed-execution.md)。
- **CLI/MCP 注册与 Agent 范围注入**：TUI `/cli` 管理自由文本 CLI usage contract（多行编辑器），`/mcp` 管理 MCP server；两类条目均可启停，`inject_to` 以 parent/explore/build 多选（勾选对话框）决定注入对象，粒度到单个子 Agent。CLI 内容条件性进入 system prompt，MCP 范围同时约束提示和工具可见性。详见 [changelog](changelog/2026-08-15/inject-to-multiselect-and-content-editor.md)。
- **Skill context 尾部注入**：skill 内容离开 system prompt——每次 LLM 调用按需合成瞬时 user 尾消息（`[skills]` 目录 + `[active skill]` 源路径，模型按需读 SKILL.md；不落库、压缩后重生成），TUI `/skill` 弹窗管理默认注入开关。详见 [changelog](changelog/2026-08-15/skill-context-tail-injection.md)。
- **配置按域拆分为独立文件（mcp/cli/skills/ap.json）**：`mcp_servers`/`cli`/`skills`/`autopilot` 四域键硬切出 `config.json`（遗留键加载时忽略，**breaking**）——各自经专属域文件 `<workdir>/.opencoder/{mcp,cli,skills,ap}.json`（项目）或 `~/.opencoder/{mcp,cli,skills,ap}.json`（全局）加载/保存，项目存在则整体遮蔽全局。详见 [changelog](changelog/2026-08-16/split-domain-config-files.md) / [autopilot 域 changelog](changelog/2026-08-20/envs-autopilot-domain.md)。
- **`/envs` 环境配置管理**：每个环境是 `~/.opencoder/envs/<name>/` 完整配置快照（config.json + mcp/cli/skills/ap.json，0o600），激活后插入解析链 **project > env > ~/.opencoder > XDG**；激活期间交互式编辑（`/model` 等）落进环境层（save_target 截断）。TUI `/envs` 弹窗（列表/新建/重捕获/删除）、web `/api/envs` REST、CLI `config show` stderr 提示行。详见 [changelog](changelog/2026-08-16/envs-config-management.md)。
- **持久化 TODO 工作流**：`opencoder todos validate/run/resume/show/events/list/interrupt` 执行预编译通用 TODO 合同；父 Workflow Session 管理全局依赖、状态、并发、验收和回退，每个 TODO 使用独立 Primary Session 聚焦完成。Store 是权威状态，`--debug` 才生成可索引文件投影。详见 [TODO 工作流](todos/index.md)。
- **结构化提问（question 潜工具门控）**：`question` 是 latent 工具（`tools/latent.rs`，同组含 `ssh_pty`）：plan agent 始终可见，act 需 skill 解锁（仅 `task-plan`：加载的 skill 名为 `task-plan` 或正文前 500 字符含该名；review 不再解锁 question，澄清走先查再定 + assumptions）才注入 schema；TUI 弹出对话框（预设选项 + 自定义输入），作答作为 tool result 同轮回填驱动继续；headless/web 无监听时固定文案兜底不挂起。完整参数与调用示例内嵌于 task-plan SKILL.md「澄清协议」段（skill 文本是唯一文档面）：[changelog](changelog/2026-09-02/task-plan-question-usage-in-skill.md)；2026-09-02 收敛完成——plan 基础提示词（`PLAN_SUFFIX`）与工具 schema `description()`（仅剩一句标识+指针）不再携带任何 question 描述：[changelog](changelog/2026-09-02/question-doc-single-source-task-plan.md)；详见 [changelog](changelog/2026-08-14/plan-question-tool.md)、ask-by-default 沿革 [changelog](changelog/2026-08-21/plan-question-always-ask.md)。
- **act/plan 双模式与显式交接**：act 为执行模式，plan 为只读探索模式；`/act`、`/plan` 与 Ctrl+T 都只切换状态并保留上下文。`/act_clear_context`（legacy `/clear_context`）是显式执行交接：plan 下保留最新真实计划、切到 act 并立即执行，act 下只保留最后回复作中性接续；transcript 只剩 synthetic 边界时再次 clear（二次确认 / resume 后 clear）原样保留已持久化边界，Plan 卡与执行指令不丢，仅从未保留过边界才空白开局。运行时不再维护 `plan_snapshot`/`plan_input_count` 相位状态，schema v10 两列仅兼容旧库；interlude 的 `agent='sandbox'` 读取时归一为 plan。详见 [agents/session](../agents/session/index.md) 与 [回退 changelog](changelog/2026-08-31/plan-mode-restore-from-sandbox.md)。
- **会话恢复**：CLI `--session <id>` / `--continue` / `--fork`，跨进程从 libsql 重建历史；title 由 small_model 异步生成。详见 [agents/session](../agents/session/index.md)。
- **Session 二进制导出/导入**：`opencoder session export <id> -o <file>` 导出 session（含 subagent 树）为 `.opencoder` 二进制文件（`OPENCODR` magic）；`opencoder session import <file>` 幂等导入到新环境，`--session <id>` 可继续执行。不导出 Config（API key 安全）。详见 [agents/store](../agents/store/index.md) / [bundle changelog](changelog/2026-07-06/compact-clear-display-session-bundle.md)。
- **模型与压缩配置化**：`providers` 命名表（`base_url/api_key/model/headers`）+ `model = "{provider}/{id}"` 选择、`small_model`、`context_limit`、`max_tokens`、`reasoning_effort`、`compaction.{auto,context_threshold,reserved,tail_turns,buffer}`、自定义 HTTP `headers`（`{ENV_VAR}` 解析）全可经 opencoder.json / 环境变量 / CLI flag 配置；压缩首轮即可由 token 估算触发。TUI `/config`（生成参数）与 `/model`（Provider CRUD + headers）分治。详见 [agents/session](../agents/session/index.md)、[agents/core](../agents/core/index.md)、[压缩提示词+token 追踪修复](changelog/2026-07-11/compaction-prompt-and-token-tracking.md)。
- **推理显示（max/xhigh）**：`💭 Thinking` 标签在高推理档位可靠且在首个推理帧到达时立即出现。上游 `extract_reasoning` 接受 `reasoning_content`/`reasoning`/`thinking` 等别名与结构化 thinking 块，末帧回退受双发射守卫保护；TUI 仅合并已显示折叠块的后续隐藏增量，不再吞掉新块首帧。详见 [agents/llm](../agents/llm/index.md) / [agents/tui](../agents/tui/index.md) / [max-xhigh reasoning changelog](changelog/2026-08-08/max-xhigh-reasoning-thinking-label.md) / [Thinking 首帧可见 changelog](changelog/2026-08-08/thinking-first-frame-visible.md)。
- **助手输出精简（保义归一化）**：每轮助手文本在流式送达 UI 后、持久化与回送上下文前，经确定性纯函数 `streamline` 归一——去散文尾部空白、连续空行收敛为单行、裁首尾空行；**fenced 代码块逐字节透传**，确保保义。单点同时削减存储与后续 input token，零额外 LLM 调用。由 `output_streamline` 配置子段驱动（`collapse_inline_ws` opt-in）。详见 [output-streamline changelog](changelog/2026-07-25/output-streamline.md)。
- **steer / followup（两段式 delivery）**：运行中的会话可在 turn 边界吸收 steer（重置步数配额），idle 时消费恰好一条 queue。HTTP `POST /prompt` 带 `delivery`。详见 [agents/session](../agents/session/index.md)。
- **侧车问询（TUI `/sidecar`）**：运行中或空闲键入 `/sidecar <问题>` 即开临时侧车对话——主任务继续执行零打断（不经 steer/queue/prompt），侧车以主会话上下文快照为解答背景、聚焦框内可连续追问（chip=`sidecar`），Esc 退出即销毁（在飞回合中止、排队问题连 backlog 一并丢弃、零残留成本）；侧车内容零落库，token 成本以裸 usage 记账到主会话，`/compact` 或重建视图后不复活旧对话。详见 [agents/tui](../agents/tui/index.md) / [sidecar changelog](changelog/2026-09-02/tui-sidecar-question-actor.md)。
- **Web 会话操作**：HTTP CRUD + SSE 事件流（replay+live）+ 运行时 agent/model 切换 + interrupt；会话列表支持 `?workdir=` 过滤（`workdir_hash` 戳）、事件流支持 `Last-Event-ID` 回退。详见 [agents/web](../agents/web/index.md)。
- **Web question 交互闭环**：plan（或已解锁 `question` 的 act）在 web drain 下等待作答——`GET /api/sessions/:id/questions` 轮询（attach-on-poll）+ `POST .../questions/:call_id/answer|skip`，前端 1.5s 轮询卡片（选项按钮/自由文本/跳过、乐观 resolve）；最后一个 SSE 订阅者断开时 abandon → 工具得 SKIPPED。详见 [changelog](changelog/2026-08-21/web-tui-parity-server-client.md)。
- **Web queue/steer 输入管理**：`GET /inputs?delivery=queue|steer`、`DELETE /inputs/:seq`、`POST /inputs/reorder`；前端 pending 输入抽屉（删除/重排/badge 计数）。详见同 changelog。
- **Web annotation/autopilot/agent 端点**：`POST /annotation`（requirement 设置/清空）、`POST /autopilot`（会话级 off|ap|review override，null 清除）、`POST /agent`（act|plan 纯切换 + 持久化，`PlanHandoff`/`ResetPlanPhase` 随双模式删除——drain 中一律 409）。详见同 changelog。
- **Web 模型/技能发现端点**：`GET /api/models`（脱敏——永不返回 api_key/headers，去重下拉列表）、`GET /api/skills`（仅 name/description/enabled）；前端模型下拉从端点拉取（自定义回退）。详见同 changelog。
- **Web 会话标题 LLM 生成**：首次 drain run 成功后 best-effort small_model 生成（30s 超时，已有 title 跳过，失败非致命）。详见同 changelog。
- **Web 前端模块化 + SSE 重连**：assets 拆为 8 模块（api/sse/sessions/chat/composer/questions/queue_panel/settings，各 ≤400 行，编译期内联单二进制）；SSE 断线重连（`/seq` + `?after=` 续订，5 次退避 1..16s，badge+banner）。详见同 changelog。
- **高性能本地存储**：libsql 嵌入 + WAL，并发读写；`Store` trait 为切换其它 Rust SQLite 实现留口子。详见 [agents/store](../agents/store/index.md)。
- **glm5.2 端到端（深度契约）**：`scripts/e2e_glm.py`（`scripts/e2e-glm.sh` 为薄 wrapper）用真 glm5.2 验证**业务契约**而非表面标记。深度观测面为 `opencoder session show <id> --json`（meta + 全 ContentBlock + subagent_tasks，解耦存储内部）。覆盖 cli E1–E19、web E11/E15/E18b、免 key 配置面 E20（`scripts/e2e/config_scenarios.py`：E20a env 覆盖 / E20b api_key 掩码 / E20c envs 激活 banner / E20d malformed `--model` 拒绝，`--only cli|web` 两种模式都跑）：E7/E9 reasoning_effort/interleaved_thinking 显示、E1/E6 write+bash 写游戏并编译（含「工具真被调用」日志断言）、E2 `--continue` 恢复**且加载了首轮上下文**（历史含 turn-1 内容）、E5 `--fork` **复制消息且原 session 角色序列/计数不变**、E3/E3b 压缩自动触发 **+ 摘要引用实际工作 + 压缩后上下文可用**、E4 subagent 派遣 **+ DB 跟踪到终态 + 父答案引用调查**、E8 bundle 导出/导入 **roundtrip 完整性（消息计数相等 + 文本内容相同 + 角色序列相同）**、E10 只读 agent **不可写盘（plan 只读契约）**、E12 session list+delete 生命周期、E13 交错思考 reasoning_content 持久化、E14 config show 合法 JSON、E11 web **两段式 delivery（steer 即时 + queue idle 消费，两个 prompt 都投递）**、E18 autopilot **自驱动循环 CLI 全链路**（config 合并 `{"mode":"ap"}`/max_iterations + display 阶段标记 Plan/Act/Verify(iteration 0) + 注入 phase prompt 落库）、E18b web SSE **autopilot 阶段事件流**（`event: autopilot` PLAN→ACT→VERIFY + 终态 done）、E15 web **interrupt**（`POST /interrupt` 中止运行中 turn，cancel token 按 drain 刷新 + 会话存活）、E16 title 异步生成（SOFT）、E17 kill -9 崩溃后 `--continue` 跨进程恢复（SOFT）、E19 todos **run→resume→observe 工作流链**（workflow_id/observe 契约 hard，终态 soft）。模型依赖项用 soft-skip；确定性存储契约（fork/bundle/resume/plan 只读）用 hard assert。注：交错思考的 reasoning_content 真实回传契约仅在强制该行为的模型（DeepSeek-V4）上可完整验证；持久化逻辑由集成测试 `session/tests/interleaved_thinking.rs` 覆盖。
- **TUI**：3-region 布局、可折叠 Thinking/Compaction、工具调用 step 阶梯（同日二次重构为三级下钻：组行 `❯ N steps [running|error]` 默认收起，点开见步行 `❯ Step(k)`，步内 thinking 直接渲染 + `❯ N function calls` 聚合行，点开见每 call 行再展开 input/output；thinking 永不出现在 step 阶梯之外（工具轮吸收进步内；纯文本轮/收尾轮/边界前滞留/task-only 轮一律折叠为「零调用 step」而非独立 Thinking 块，live + replay + SPA 快照三路径同源）；Ctrl+L 一键收齐、Say 永不折叠——SPA 与 TUI 两侧均已落地，[恒展开 changelog](changelog/2026-09-03/step-ladder-unfold-tui-spa.md) / [SPA 三级下钻 changelog](changelog/2026-09-03/spa-step-ladder-three-level-drill.md) / [TUI 三级下钻 changelog](changelog/2026-09-03/tui-step-ladder-three-level-drill.md) / [thinking 全折叠 changelog](changelog/2026-09-03/thinking-never-outside-step.md)）、subagent ctx 视图、steer/followup、会话切换、notepad 与 copy mode。模式快捷键明确分工：Ctrl+T 保留 transcript/composer，在 act↔plan 间纯切换；Shift+Tab arm 5s 倒计时，保留 plan 并切 act 开始执行，草稿作为附加需求一并交接，Esc 可回撤；倒计时内输入框保持可编辑，任一次提交（Enter 或再按一次 Shift+Tab）立即执行并把键入内容并入附加需求，不必等满 5s（kitty Release 半事件一律 inert）。clear-confirm fire 双路径：手动确认 running 态先按 double-Esc 同语义打断当前轮再立即执行，无人确认到期保守排队（附 `[clear] 已排队` marker）；Ctrl+T 等其余模式命令与文本命令同语义：**提交即入队、非 running 才生效**——idle 立即起 control-command turn，running 时原文入队由 runner 在 idle 边界 drain intercept 应用，按键永不丢失（steer/queue 同族）。plan idle 时 Shift+I 可编辑计划。详见 [agents/tui](../agents/tui/index.md)、[模式切换 gate](changelog/2026-08-08/mode-switch-running-gate.md) 与 [clear-context 倒计时](changelog/2026-08-29/clear-context-countdown-guard.md)、[Shift+Tab 再按确认](changelog/2026-09-02/shift-tab-repress-confirms-armed-clear.md)、[手动确认打断立即执行 + Release/入口对称修复](changelog/2026-09-02/clear-confirm-manual-fire-interrupts-and-release-guard.md)、[切换 running 入队](changelog/2026-09-02/mode-switch-running-queues-at-idle-boundary.md)。
- **autopilot 三态模式**：`config.autopilot.mode`（`off` / `ap` / `review`，默认 `off`；旧布尔 `enabled` 在 config 合并层迁移 true→ap / false→off，mode 键优先）。初始任务完成后 runner 按 mode 分发：`ap` → `autopilot::drive` 反复执行 PLAN→ACT→VERIFY 直到 VERIFY（PLAN = 切 plan agent + 激活 task-plan skill + 合成 continuation_prompt 跑单次 run_loop；ACT = `handoff::reset_to_directive` 折叠出规划简报后以 execute_prompt 执行；small_model 隔离 shadow 一次性调用，判定交换不写入主 transcript；判定**严格单 token** 解析——限定性回答如 "Yes, but…" 视为无判定重试）回答「完成」、`verify_retries` 次内无可解析判定（Aborted reason 区分成因：verdict unparseable / judge unreachable，后者携带最后一次传输错误）、或已完成迭代达 `max_iterations`；`review` → `autopilot::review_pass` **agent 无关**（runner 对任意 primary agent 放行，评审者留在完成该轮 run 的当前 agent 上，不切换）**一次性** review turn（iteration 固定 0 + 激活 review skill + 合成 review prompt 跑单次 run_loop，不进 ACT/VERIFY，结束清 skill 并发 `Done`）；`off` → 无任何自动行为。每阶段发 `SessionEvent::AutoPilot` 进度事件（含 `Review` phase；TUI 状态栏 / CLI / web SSE 可观测）；doom-loop / tool-failure guard 在 `run_loop` 内按**单次 run（即单个 phase）作用域**累计——phase/迭代边界重置、跨迭代不累计，整轮循环由 `max_iterations` 兜底；cancel 在 drive 循环边界检查（`review_pass` 入口亦有 pre-flight 取消检查）；todos workflow 路径强制 off。TUI `/ap` 打开三选一模式菜单（选择即保存），chip：ap→`AP`、review→`RV`；`/model` 表单保留 `max_iterations` 编辑。详见 [agents/session](../agents/session/index.md) / [autopilot changelog](changelog/2026-07-28/autopilot-loop.md)。
