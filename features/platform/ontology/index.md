# Ontology

Web 导航提供独立 Ontology 分类：图谱、实体、实体类型、关系类型、数据保鲜。页面使用所连接 OpenCoder Server 的默认数据空间，不提供环境选择或环境管理，浏览器保存的旧环境选择不参与请求。复用 OpenCoder 登录和权限，分类标签可横向滑动，内容区域不重复展示页面标题和说明。

## 操作与权限

- `opencoder-cli ontology` 提供数据操作、能力查询及同步命令，见 [CLI 用法](../../../rules/10-ontology-cli.md)，可复用 [opencoder-ontology skill](../../../skills/opencoder-ontology/SKILL.md)。平台能力目录包含全部平台功能入口和六类原生可执行能力，图谱通过明确依赖组织能力。Web 在实体页通过实体类型筛选和搜索定位能力实体，图谱可选择同名切面。
- CLI 支持类型、属性、Action、实体、关系、切面、目录与数据空间的创建、查询、更新和软删除；实体详情、关联关系和图谱范围可单独查询。新实体通过 `directory_id` 归入实体目录，已有实体通过目录归属关系挂载或解除，子目录通过 `directories move` 调整父目录。
- Server 启动与能力修改后自动同步，另每 30 秒检查补漏。同步状态、失败原因和最后成功时间可查询，失败保留上次成功内容并继续重试；调用方也可主动检查或补同步。
- 托管发布中只允许当前版本的当前 Server 实例同步写入；候选预热只允许检查差异，切换和回滚准备期间暂停同步写入。被拒绝的同步不改变共享目录或状态。发布记录缺失时同样拒绝写入，独立 Server 不依赖该记录。
- 候选预热和普通重启不自动修改已有数据库结构。缺表、缺索引或缺少系统数据时，暂存和启动会提示维护升级；结构冲突直接拒绝。维护流程停止旧服务、验证不可变备份后，才授权指定候选执行事务迁移；开放写入后不能恢复旧备份。独立 Server 只自动初始化空库。
- 原模块维护能力定义和执行。Ontology 中自动生成的字段通过来源入口修改，人工补充说明、自定义属性与关系在后续同步中保留；运行状态和执行记录不复制到目录。

- admin 与 editor 在页面中创建、编辑和软删除类型、属性定义、Action 配置、实体、关系与图谱切面。viewer 可浏览全部 Ontology 页面和执行向量搜索，不能修改数据。
- Server 默认数据空间初始化系统根、目录类型和目录关系；保存与查询不能跨数据空间引用对象。
- 类型支持自定义属性及 source/ext 正文，属性定义可直接编辑；实体编辑使用 revision 防止覆盖他人修改。
- Action 支持读/写操作的配置与停用，不触发执行。
- 目录节点单父且不能成环；普通实体可挂多个目录（同一目录重复归属被拒）；系统目录类型及关系不能随意改写。
- 实体可按名称和类型筛选；类型、关系等列表提供筛选和错误重试。关系受源、目标类型约束，删除等危险操作收进操作菜单。
- 2048 维向量可写入、读取及按余弦相似度搜索，拒绝长度错误、非有限值和零向量。

## 详情与编辑

- 实体详情分为基本信息、普通属性、拓展信息、来源四个标签；相关实体和关系可继续打开，返回时恢复原标签与滚动位置，也可选择当前实体作为图谱中心。
- 结构化属性支持直接编辑；正文默认预览，支持 Markdown 和 HTML 源码编辑。HTML 预览使用隔离页面，保存时保留原格式；NFS 属性编辑相对路径并展示引用的正文。
- 草稿在详情标签之间保留。关闭详情、更换实体、切换页面、退出时提示放弃未保存修改；保存期间阻止离开和重复操作，浏览器关闭也有离开提示。
- 保存失败保留输入。保存成功但刷新失败时明确提示已保存，后续编辑使用已提交的新版本。

## 图谱观测

- 图谱使用三维空间网络展示节点与关系，沿用页面配色。节点按类型区分颜色，中心和选中项突出显示，关系带方向箭头；双向、多重关系分开绘制。节点和关系标签保持正向，关系名称完整换行。

- 选择实体类型后自动展示观测范围内关联的其他类型实体，页面不提供“展开跨类型邻居”开关。支持多个中心、独立上下游跳数和关系筛选；通过“调整范围”修改条件，可保存命名切面并再次观测。
- 观测链接支持 `#ontology_aspect=<切面 key>&ontology_center=<实体 ID>`，可选 `ontology_upstream`、`ontology_downstream`（0–9）。打开时优先应用链接条件；对象失效时提示并恢复可用范围。离开图谱页时清除链接条件，不修改保存的切面。
- 页面记住最近一次成功观测的类型、关系、中心、跳数和命名切面；未应用或失败的范围不覆盖成功记录，恢复前检查引用对象是否仍有效。
- 画布起始展示最多 30 个节点、60 条边，可逐步展开；完整查询结果提供列表、搜索、详情和图中定位。中心超过 30 个时先展示列表。
- 鼠标拖动空白处旋转、滚轮缩放、右键平移；触屏单指旋转、双指缩放和平移。工具栏提供缩放、重置视角、概览、中心定位和放大画布。定位观测中心一次点击生效；切换命名切面后等待布局完成再居中。相同结果刷新保留布局，展开、详情及容器尺寸变化保留相机视角。
- 三维布局稳定后停止节点运动，隐藏画布暂停绘制。浏览器无法创建三维画布或绘图连接中断时，显示原因并回退完整结果列表，可重试三维画布。三维坐标只存在前端，不写入实体或切面记录。
- 查询失败时保留已有成功结果并显示错误和重试入口，同时区分查询范围与当前画布展示数量。

## 保存与错误

- 新实体的幂等请求 ID 在相同环境和调用身份内复用原回执；复用 ID 却改变内容返回 409。
- 每个写请求整体成功或回滚，包括属性、审计和当前正文版本；客户端断开后已接纳写入仍完成，Server 退休等待这些写入。
- 版本冲突和正文引用变化返回 409，字段校验失败返回 422，权限不足返回 403。读取失败有明确错误与重试入口，不显示为正常空列表。
- 软删除保留历史数据。正文文件不可覆盖，引用携带摘要及字节数；单份正文最多 4 MiB。

## 正文共享与升级

正文通过本服务独立只读 NFS 导出，共用现有资源服务。默认关闭；显式启用的配置示例：

```json
{
  "ontology": {
    "files_dir": "/srv/opencoder/ontology-files",
    "nfs": { "enabled": true, "host": "127.0.0.1", "port": 2052 }
  }
}
```

正文目录须为绝对路径，并与 Agent、二进制和源工作区目录分开；不能把 Server 数据库包含在导出中。`files_dir` 可省略，默认位置由 Server 工作目录对应的数据根决定。`host` 按实际客户端网络配置，端口不能与其他导出重复，导出始终只读。

数据库首次初始化后，正文目录固定。修改或删除已有的显式 `files_dir` 会被维护预检拒绝；直接启动使用不同目录也会失败。相同目录的规范化路径别名可以复用。备份恢复保留原目录绑定，不能通过改配置迁移正文。

跨数据格式升级须使用维护流程；当前格式和兼容范围以发布说明为准。备份和恢复必须同时包含 ontology.db 与实际正文目录；外部正文目录也纳入备份。具体流程见 [平滑发布验收](../../../scripts/acceptance/smooth_release/main.py)。

## 目录管理

实体页内容区为 Tabs【目录 | 实体】，默认“实体”；目录管理集中在“目录” tab，CLI 维护途径保持可用。

- Tabs：“实体” tab 展示全量实体表格（含未归入目录的实体）与「所属目录」列，搜索、类型筛选、状态筛选和分页作用于全量列表；普通实体的多个目录归属以多个 Tag 展示，点击某个 Tag 切换到“目录” tab 并选中该目录；“目录” tab 左侧为目录树，右侧为成员面板。
- 树编辑：通过右键或更多菜单执行新增子目录、重命名、删除、移动到…，行内草稿输入并在同名时即时校验；节点支持拖拽移动；根目录仅可新增子目录，不可重命名、删除或移动。
- 成员管理：添加实体支持多选并排除已有成员，移出成员即软删除对应目录归属；服务端拒绝的错误（如删除非空目录）在面板透出提示。

## 数据保鲜

数据保鲜为实体增加四级数据级别与复核流水线：按实体类型配置策略，由平台执行（agent 或 DAG）生成候选正文，人工评审通过后实体级别逐级上升。策略、运行与评审保存在 Ontology 数据库；运行派发由控制面唯一驱动，数据平面只提供读写接口。

- 数据级别：实体携带 `data_level`，四级阶梯 draft < stable < verified < confident；旧实体读取时默认 draft，无需迁移。评审通过恰好提升一级，confident 保持不变；拒绝只记录评审历史，不改级别。
- 策略：绑定一个实体类型与执行器（`kind` 为 `agent` 或 `dag`、`target`、`prompt_template`），并发上限 1–30，可选 `writeback_attribute_key` 指定回写的 Markdown 正文属性（如内置的 source）。提示词模板渲染 `{{entity.id}}`、`{{entity.name}}`、`{{entity.description}}`、`{{entity.data_level}}`，未知占位符替换为空。
- 运行：控制面 `POST /api/ontology/envs/:env/freshness/policies/:id/runs` 触发（202）。运行快照至多 500 个该类型的未删除实体；派发使用确定性执行 ID（`agent-`/`dag-` 前缀 + 哈希）并走标准执行提交准入，按策略并发有界扇出，5 秒节奏轮询执行索引至终态、上限 1 小时；候选摘要至多 8000 字符，DAG 输入冻结实体快照。无可用节点时对应项记为失败，运行继续收敛。运行从 queued/running 收敛为 succeeded/partial/failed。
- 重启回收：控制面重启后恢复挂起运行——已到终态的执行补齐候选，未派发项记为 interrupted before dispatch；每运行请求锁跳过仍由活跃驱动器持有的运行，避免双写。
- 评审：`POST /api/ontology/envs/:env/freshness/reviews`（body 为 `run_id`、`entity_id`、`verdict`、可选 `comment`）单事务完成。重复评审返回 409；通过要求该项成功且带候选；能力目录托管的实体与属性不接受评审写回（409）；配置回写时生成不可变 Markdown 正文版本；`data_level` 提升一级并递增实体 revision，全程审计。`GET /api/ontology/envs/:env/freshness/reviews?run_id=` 查询评审记录。
- 数据平面接口：`GET/POST /api/ontology/envs/:env/freshness/policies`、`GET/PATCH /api/ontology/envs/:env/freshness/policies/:id`（软删除用 PATCH 设置 `is_deleted` 并携带 `expected_revision`）、`GET /api/ontology/envs/:env/freshness/runs` 与 `/runs/:id`、评审接口同上。读取对 viewer 开放，写入需管理角色。CLI 用法见 [CLI 用法](../../../rules/10-ontology-cli.md) 的 `freshness` 行。
- 存量库升级：新增 `freshness_policies`、`freshness_runs`、`freshness_reviews` 三张 JSON 正文表，schema 版本保持 1；已有数据库经标准 `--maintenance` 维护窗口一次性补表，流程见 [维护窗口验收](../../../scripts/acceptance/maintenance_release/main.py)。
- 边界：不做定时调度、运行取消、模型预审、属性粒度级别与图谱子集圈定，留待后续阶段。变更记录见 [Ontology 数据保鲜](../../changelog/2026-10-30/ontology-freshness.md)。
