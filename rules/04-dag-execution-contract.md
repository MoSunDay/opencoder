# 规则 04：DAG 执行约定

修改 DAG 协议、调度、资源分发或工作区之前，先读本规则。代码、测试和文档必须共同满足以下约定；不能为了迁就旧实现悄悄增加兼容分支。

**验收要求：** 修改本约定涉及的实现后，必须通过真实 `runc` 端到端验证、全量回归和发布演练。功能验证不能代替发布门槛；任何必需验收未通过，都不能宣称可上线。

平滑切换的受理延迟、连续受理与调度间隔上限为 **30 秒**，不是 1 秒。隔离进程演练按最大值验收，不能用 P95 隐藏超限请求；公共入口必须无失败请求，连续成功探测的间隔也不得超过 30 秒。

## 节点与容器

- Server 是控制面，只保存定义、派发和执行索引；一次 DAG 运行及其详细记录始终归属同一个执行节点，不跨节点分拆步骤。
- 派发前确认节点支持 `dag_container_v1`；没有这项能力的节点不能接收静态或动态 DAG。动态节点还必须支持 `dag_dynamic_v1`，不能因旧节点只回复通用兼容标记就放行。
- 每次运行只启动一个 `runc` 容器。静态步骤、动态实例与 Agent 步骤都在该容器内执行，共享同一个 `/workspace`；不得恢复每步单独启动容器的做法。
- 所有步骤使用同一个执行用户；目录是组织方式，不是步骤之间的安全边界。不得重新加入步骤级运行时隔离或宿主执行回退。
- 静态步骤的工作目录是 `/workspace/<step_name>`，动态实例是 `/workspace/<step_name>/instances/<index>`。步骤名称遵循协议校验，不得与运行时保留目录冲突；保留名单以 `crates/dag/src/artifacts.rs` 为准。
- 节点必须具备建立挂载与容器的权限，rootfs 必须包含本版本的 `dag-runner` 和 `agent-step-runner`。缺少依赖时在受理前拒绝，不得让二进制步骤额外依赖模型凭证。
- 镜像中的两个运行器必须与节点的完整构建信息一致，包括提交、协议、数据格式、Brain schema 和 SPA 摘要；缺失、软链接或混用版本都在受理前拒绝。
- 保留 DAG 的依赖、并发、单步超时、取消和恢复语义。取消一个步骤只终止该步骤的进程树；结束整次运行时才关闭容器。节点重启后只在原节点用同一份运行数据恢复。

## 工作区与数据

- Server 提供的源工作区及资源池通过只读 NFS 供节点读取。每次运行只准备一次所需挂载，不能为每个步骤反复挂载。
- 源工作区不能被 DAG 改写，也不能为了启动 DAG 整目录复制。节点使用本地 OverlayFS 写层：新文件直接写入写层，修改源文件时只复制该文件；容器看到合并后的 `/workspace/<step_name>`。
- 源工作区在本次运行期间保持不变。不能通过修改源目录权限或移动源路径来让步骤获得写权限。
- 维护升级同样不能改动源工作区：源目录必须预先存在，Server 实际运行用户必须可以读取和遍历。二进制池、节点资源挂载点、安装配置和状态路径不能与源目录互相包含；按解析软链接后的路径检查，不创建源目录、不改变其所有者或权限。
- 执行节点按 `YYYY-MM-DD/<dag_id>/<run_id>` 保存本次写层、步骤产物和恢复记录；Server 不集中保存工作区文件。日期和标识符必须稳定且路径安全。
- 日期取 Server 创建时间的 UTC 日期。受理时保存实际目录与配置，重启和恢复不能根据新配置重新选择目录或资源版本。
- 步骤通过 `OPENCODER_STEP_CONTEXT` 读取只读 `meta/context.json`，通过 `output.json` 交付结构化结果。其他需要下载的文件必须在 `artifacts.json` 声明相对路径、字节数及 SHA-256；归档只复制声明的文件，不复制整块源工作区。
- 运行前从 NFS 固定每个步骤使用的二进制与 Agent 版本，仅准备本次所需依赖到该步骤的 `/workspace/<step_name>/meta/`；缺失、摘要不符或工作区无法建立时拒绝启动，不能退回宿主执行。

## 步骤能力与变更门槛

- DAG 的可执行步骤是 Linux 原生二进制或 Agent，动态节点只能展开这两种。二进制使用参数数组，资源池管理不可变版本，并在受理时固定版本。
- 任何更改上述约定的需求，先明确记录新的用户决策，再同步修改本规则、协议测试、真实 `runc` 端到端测试及仓库记忆；不能只改其中一处。
