# 规则 08：仓库只保留通用基建

OpenCoder 是通用的代理执行与调度基础设施。代码库及其开发上下文只描述平台自身能力，不保存平台所承接业务的任何信息。

## 适用范围

源码、注释、测试、样例、配置模板、内置提示词与技能、脚本、文档、仓库记忆、变更记录和提交说明都遵循本规则。生成产物也必须保持相同边界。

## 实现与数据

- 执行、调度、资源、会话、项目、TODO 和产物管理等能力保持通用。不得根据具体业务名称、目录、接口、字段含义或流程增加专用分支。
- 具体任务通过运行时输入、用户配置、能力注册和外部资源接入；相关定义、提示词、配置和执行数据留在仓库外，不作为默认值或内置样例提交。
- 测试和样例使用最小的虚构数据、通用名称、临时目录与占位地址。不得复制真实任务、用户记录、服务地址、请求内容、日志、截图或凭证。
- 可以保留实现基建所必需的上游依赖、标准协议和公开 API 名称；说明仅围绕技术接口与使用约束。

## 文档与开发上下文

- 文档、仓库记忆和变更记录只写平台职责、接口、状态、限制、故障机制及验证结果，不写具体业务背景、目标、流程或使用情况。
- 从真实任务中发现问题时，提炼为通用的触发条件和最小复现；修复说明、测试名称与提交说明均不得带入原任务信息。
- 不在清理说明、反例、禁用词清单或审查记录中重新保存被移除的业务信息。
- 使用准确的基建术语，例如任务产物、自定义步骤、应用帧、请求拒绝，避免用泛指的“业务”描述平台对象。

## 提交前核对

检查改动及其生成产物中的名称、路径、地址、示例、提示词与叙述是否越过上述边界。发现专用内容时，移到仓库外并将基建部分改为通用接口；同步清理相关注释、样例和文档，不能只换名称而保留专用实现。

本规则约束代码库内容，不授权改动运行数据库或已有鉴权数据。验证仍按 [规则 02](02-regression-gate.md) 限定范围。
